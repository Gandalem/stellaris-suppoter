# 같은 크기 무기 비교 2안 초안

함선 설계 중 같은 슬롯 크기의 무기 두 개를 골라 기본 성능·피해 특성·자원별 비용의 차이를 읽고, 필요한 무기를 기존 오버레이 카드로 남긴다. 비교의 목적은 교체할 때 얻고 잃는 것을 드러내는 것이다. 수치가 큰 무기를 자동으로 추천하거나 실제 전투 결과를 예측하지 않는다.

[1안](WEAPON-COMPARISON-OPTION-1.md)을 보존하고, 플레이 중 판단에 필요한 정보와 데이터 처리 경계를 보완한 개발 제안이다. 현재 화면·데이터 구조를 재사용한다.

## 1 1안에서 보완한 결정

| 관점 | 보완 내용 | 이유 |
|---|---|---|
| 게이머 | 기본 피해를 발당 피해로 명확히 하고 피해 배율·관통률도 기본 화면에 배치 | 피해 숫자만 보고 다른 용도의 무기를 상위 호환으로 오해하지 않게 한다. |
| 게이머 | 같은 크기 후보의 계열·조건·특수 작용을 함께 제시 | 같은 슬롯 크기와 같은 장착 조건을 구분한다. |
| 사용 흐름 | 후보 선택 중인 상태와 확정한 비교를 분리 | 대상 변경을 취소해도 기존 비교를 잃지 않는다. |
| 화면 | 한 표에서 행을 맞추고 공통 스크롤·고정 항목 순서를 사용 | 양쪽을 따로 스크롤하며 다른 항목을 읽는 일을 막는다. |
| 수치 | 반올림 전 값으로 동일 여부를 판정하고 작은 차이를 보존 | 표시상 0이 된 차이를 실제 동일로 오인하지 않게 한다. |
| 데이터 | 스냅샷의 일부 자료 상태와 개별 숫자의 해석 상태를 구분 | 번역 일부가 없다고 정상 성능까지 비교에서 제외하지 않는다. |
| 개발 | 비교 대상·행·응답을 식별자로 묶고 조회 한도를 명시 | 빠른 대상 변경과 많은 자원에서도 이전 결과가 섞이거나 일부 행이 조용히 빠지지 않게 한다. |

## 2 기본 사용 흐름

1. 관리창의 무기 상세 또는 편집 중인 무기 카드에서 무기 비교를 연다.
2. 시작한 무기를 기준 무기 A로 두고, 그 무기의 자료와 슬롯 크기를 고정한다.
3. 같은 자료·같은 크기의 후보에서 비교 무기 B를 선택한다.
4. 성능·피해 특성·제작 비용을 나란히 읽고 필요한 추가 항목을 펼친다.
5. 원하는 쪽의 상세·요구 기술·명시된 상위 부품을 열거나 해당 무기 카드를 고정한다.
6. 뒤로 돌아오면 A/B 선택과 표 위치를 이어서 사용한다.

기존 무기 검색 안의 비교 화면으로 연결한다. 비교를 열 때 게임 입력 통과 상태나 홈의 자료 선택을 바꾸지 않는다. 오버레이에서 비교를 여는 동작은 기존 편집 상태에서 제공한다. 비교 화면을 위해 게임 위에 큰 팝업을 누적하지 않는다.

## 3 후보 선택과 변경

A/B는 표시 이름 대신 스냅샷·개별 정의 식별자로 저장한다. 후보는 실제 size 값이 같은 정의만 제시한다. 소형이라는 번역명이나 ID 접미사로 크기를 추정하지 않는다. 크기가 없거나 불명확하면 비교 진입 이유를 짧게 설명하고 기존 상세를 계속 사용할 수 있게 한다.

B 선택 영역에서 한국어·영어 이름과 부품 ID로 검색한다. 계열 묶음은 개별 크기·정의로 펼쳐 선택한다. 같은 이름·같은 ID의 중복 정의는 출처를 짧게 구분하고 사용자가 하나를 고른다. 중복을 합치거나 뒤의 정의를 자동 선택하지 않는다. A와 동일한 개별 정의는 B로 확정하지 않는다.

같은 크기의 다른 계열도 선택할 수 있다. 후보와 선택 머리글에 확인된 계열·조건·특수 작용 표시를 제공한다. 새로운 전투 역할 분류를 이름으로 만들어 붙이거나, 같은 크기라는 이유로 현재 함선에 장착 가능하다고 표시하지 않는다. 추가 조건의 내용은 기존 상세로 연결한다.

대상 변경은 임시 후보 선택으로 시작한다. 취소하면 기존 A/B·표·스크롤을 유지한다. 확정하면 새 선택을 표시하고 이전 차이 표를 비운 뒤 새 결과를 읽는다. B가 없는 첫 화면에서는 A 정보와 후보 선택을 보여주고 차이 칸을 계산하지 않는다.

A 변경을 확정했을 때 기존 B가 같은 자료·크기의 다른 정의라면 유지한다. 크기가 달라지거나 A와 같은 정의가 되면 B를 비운다. 자료 변경은 새 자료에서 두 대상을 고르는 별도 흐름으로 처리한다. 후보가 0개면 같은 자료·크기의 다른 무기가 없음을 표시하고 검색어 지우기와 뒤로 가기를 제공한다. 조회 실패를 후보 0개로 표시하지 않는다.

A/B 바꾸기는 두 대상이 확정됐을 때 제공한다. 두 이름과 값·조건·개별 카드 동작을 함께 교환하고 모든 차이의 방향도 뒤집는다. 단순히 머리글만 바꾸지 않는다.

## 4 비교 화면

상단에 A 기준 무기와 B 비교 무기의 이름·크기·계열, 대상 변경과 A/B 바꾸기를 둔다. 이름이 같아 구분이 어려울 때만 ID·출처의 짧은 식별 정보를 덧붙인다. 긴 파일 경로나 진단 정보로 기본 화면을 채우지 않는다.

본문은 항목 / A 값 / B 값 / 차이(B−A)의 한 표로 구성한다. 두 무기의 같은 항목은 같은 행에 고정한다. 행을 성능 순위처럼 정렬하는 기능은 넣지 않는다.

| 순서 | 기본으로 보이는 항목 | 표현 |
|---|---|---|
| 1 성능 | 발당 피해 범위, 최소·최대 사거리, 기본 명중률·추적률, 소비/공급 전력 | 피해 최소/최대와 사거리 최소/최대를 구분한다. |
| 2 피해 특성 | 보호막·장갑·선체 피해 배율, 보호막·장갑 관통률 | 다른 방어층에 대한 특성을 기본 피해와 함께 읽는다. |
| 3 제작 비용 | 자원 ID별 고정 비용 | 합금·에너지·희귀 자원을 각각 표시한다. |
| 4 추가 항목 | 유지비, 발사 간격·최소/최대 준비 시간의 원문 값 | 시간은 단위 환산과 차이 계산 없이 참고 값으로 표시한다. |

발당 피해가 높다는 사실을 화력이나 DPS 우위로 요약하지 않는다. 발사 간격은 기존 조회에서 확인한 원문 값을 읽을 수 있게 하되 시간 단위를 새로 가정하지 않는다. 확인하지 못하는 특수 작용은 계산 표에 숫자로 끼워 넣지 않고 무기별 상세 연결로 남긴다.

조건·특수 작용의 짧은 표시와 자료 기준은 표 주변에 한 번씩 둔다. 공통 안내를 각 숫자 행에 반복하지 않는다. 비교가 가능한 행 개수로 전체 정확도나 개발 진행률을 만들지 않는다.

하단에는 A 상세 / A 카드 고정 / B 상세 / B 카드 고정을 대상별로 묶는다. 표의 행 선택이 고정할 무기를 바꾸지 않게 버튼에 대상 이름을 연결한다.

## 5 차이의 의미와 숫자 표시

차이는 항상 B−A다. +는 값 증가, −는 값 감소이며 우열 판정이 아니다. 소비 전력·비용 행에도 같은 방향을 쓰므로 숫자 옆의 항목명과 단위를 유지한다. 색에 더해 부호·동일·비교 불가를 문자로 구분한다.

| 항목 | 계산 규칙 | 표시 예시 |
|---|---|---|
| 발당 피해 | 확인된 최소끼리·최대끼리 각각 계산 | A 8–21, B 13–35 → 최소 +5 / 최대 +14 |
| 피해 범위가 교차 | 각 끝값의 차이를 그대로 표시 | A 8–21, B 10–20 → 최소 +2 / 최대 −1 |
| 사거리 | 최소와 최대를 각각 비교 | 최소 −5 / 최대 +10 |
| 명중·추적·관통 | 원래 비율의 차이를 퍼센트포인트로 변환 | 90% → 95%는 +5%p |
| 피해 배율 | 동일한 배율끼리 차이를 계산 | ×1.25 → ×1.50은 배율 +0.25 |
| 같은 자원 비용 | 같은 자원 ID·같은 비용 종류의 확정 값끼리 계산 | 합금 15 → 23은 +8 |

예시는 표시 규칙 설명용이다. 특정 무기의 실제 수치로 고정하지 않는다. 평균 피해·상대 증가율·DPS·회피 반영 적중률·제국/함선 보정·승률·총점과 추천 순위는 이번 범위에 넣지 않는다.

계산은 표시 문자열이 아닌 확인된 십진 숫자로 한다. 반올림 전 차이가 정확히 0일 때만 동일로 표시한다. 정상적인 작은 차이가 기본 표시 자릿수에서 0이 되면 필요한 소수 자릿수나 명확한 과학 표기를 사용한다. 음의 0을 증감처럼 표시하지 않는다. 값과 차이가 서로 모순돼 보이면 해당 행의 표시 정밀도를 함께 높인다. 중요한 숫자의 끝을 생략 부호로 잘라 버리지 않는다.

필드의 단위·해석 규칙이 맞지 않으면 두 숫자가 있어도 차이를 계산하지 않는다. 유한 숫자·정상 범위·확정 상태를 모두 확인한다. 최소/최대가 뒤집힌 범위를 고치거나, 빠진 끝값을 다른 끝값으로 복제하지 않는다. 독립적으로 확정된 끝값만 비교하고 나머지는 해당 상태로 남긴다.

## 6 전력·선언 없음·기본값

전력은 기존 해석에 따라 소비와 공급을 셀 안에 표시한다. 양쪽이 모두 소비라면 소비량끼리, 모두 공급이면 공급량끼리 차이를 계산한다. 예를 들어 소비 7 → 소비 13은 소비 +6이다. 소비와 공급이 바뀌면 유형 변경으로 표시한다. 양쪽 모두 명시적 0이면 동일이며, 0과 소비/공급 간 전환은 해당 유형과 양을 직접 보여준다. 함선 잔여 전력이나 발전기 교체량으로 확장하지 않는다.

필드에 선언이 없다는 사실과 숫자 0은 다르다. 최소 사거리·관통률·배율·자원 비용에 선언이 없으면 기존 조회 정책의 상태를 유지한다. 게임 문서의 기본값을 이번 화면에서만 새로 채워 넣지 않는다. 향후 기본값을 지원할 때는 조회와 카드의 공통 해석 규칙을 먼저 정한다.

같은 미확정 상태가 양쪽에 있다는 이유로 동일로 표시하지 않는다. 정확한 0끼리의 비교와 구분한다.

## 7 제작 비용과 유지비

양쪽에 선언된 자원 ID의 합집합으로 행을 만든다. 번역 이름이 같아도 ID가 다르면 별개이며, 번역이 없으면 ID로 구분한다. 제작 비용과 유지비는 별도 구역에 둔다. 서로 다른 자원을 단일 가격으로 환산하지 않는다.

양쪽에 같은 자원의 단일 고정값이 확인되고 그 범위에 추가 선언이 없다고 판단할 수 있을 때만 차이를 계산한다. 한쪽 선언 없음은 0으로 채우지 않는다. 명시적 0은 일반 숫자로 비교한다.

기존 resource_scopes와 개별 해석 상태를 재사용한다. mult/multiplier·조건문·인라인 스크립트는 자원이 아니다. 동적 계산·중복 블록·잘린 범위를 합산하거나 마지막 값으로 확정하지 않는다. 알려진 값만으로 총비용을 만들지 않는다. 비용 전체가 동적이어도 정상 성능 행은 계속 비교한다. 비용 구역과 유지비 구역은 서로 독립된 상태를 유지한다.

자원 행은 ID 기준의 안정된 순서로 맞춘다. 많은 자원은 양쪽의 합집합을 기준으로 페이지를 나누며 A와 B를 따로 넘기지 않는다. 기본 성능 행은 자원 페이지를 바꿔도 유지한다. 일부 범위만 읽었으면 표시 범위와 이어 읽기를 알리고 전체 목록인 것처럼 보이지 않게 한다.

## 8 미확정 값·오류·자료 기준

셀에는 숫자 또는 짧은 상태를 표시한다. 선언 없음 / 자료 없음 / 중복 / 동적 계산 / 변이 규칙을 구분하고 차이 칸에는 비교 불가를 둔다. 같은 원인의 자세한 설명은 A/B 각각 한 곳에 요약한다. 필요한 이유를 마우스 올리기에만 숨기지 않는다.

변이 무기를 선택해도 기존에 확인된 정적 항목과 요구 기술·상위 부품을 사용할 수 있다. 미확정 변이 수치나 동적 비용을 비교 화면에서 새로 해석하지 않는다. 변이 안내를 숫자 행마다 반복하지 않는다.

스냅샷이 일부 자료라는 상태와 개별 수치의 해석 상태를 구분한다. 일부 번역을 못 읽었다는 이유로 출처와 숫자가 정상인 성능을 모두 지우지 않는다. 반대로 정상 스냅샷이라는 이유로 미확정 필드를 확정하지 않는다.

출처 손상·다른 정의와의 결합·자료 불일치는 일반 미확정과 구분한다. 해당 비교 결과를 비우고 현재 선택을 유지한 채 다시 읽기 또는 대상 변경을 제공한다. 이전 결과로 실패를 덮거나 읽기 실패를 값 없음으로 바꾸지 않는다. 고정 동작은 선택한 개별 정의와 현재 자료가 정상 확인된 경우에 제공한다.

자료 기준은 공통 영역에 기본 파일 기준·이전 자료 여부·일부 자료 여부를 필요한 만큼 한 번 표시한다. 설치 버전·DLC·모드 활성 상태를 확정할 자료가 없으면 추정하지 않는다. 사용자가 제거한 값의 근거 패널은 다시 추가하지 않는다. 내부 출처 검증과 기존 상세/원문 연결은 유지한다.

## 9 스냅샷·언어·뒤로 가기

비교 한 건은 하나의 스냅샷에 고정한다. 관리창에서는 선택한 조회 자료를, 과거 카드에서 시작하면 그 카드의 자료를 사용한다. B 후보 검색도 홈의 최신 자료가 아니라 현재 비교 자료에 묶는다. 다른 스냅샷의 카드 둘을 곧바로 혼합하지 않는다.

색인이 끝나도 열린 비교의 자료·값을 자동 교체하지 않는다. 새 자료로 비교를 누르면 새 자료에서 A/B를 다시 고른다. 이전 비교는 기존 뒤로 가기 이력에 남긴다. 과거 고정 카드와 홈 자료는 자동 갱신하지 않는다. 과거 자료에 없는 값을 현재 설치 파일에서 보충하지 않는다. 두 무기 비교와 패치 전후 비교는 별도 흐름으로 둔다.

상세·요구 기술·명시된 상위 부품으로 이동했다 돌아오면 A/B·후보 검색어·추가 항목·표 위치·초점을 복원한다. 기존 최대 32개 이력을 사용한다. 언어를 바꿔도 같은 개별 정의를 유지하고 번역만 다시 읽는다. 비교 선택과 화면 상태는 실행 중에만 유지하며 재시작 시 초기화한다. 기존 고정 카드 복원 방식은 그대로 사용한다.

## 10 카드 고정과 화면 조작

A/B의 고정은 기존 개별 무기 카드 기능을 호출한다. 같은 카드가 있으면 기존 카드를 선택하고 위치·크기·표시 항목을 바꾸지 않는다. 공유 24장 한도를 그대로 사용한다. 빠르게 두 번 눌러도 중복 카드가 생기지 않게 기존 식별·저장 절차를 사용한다. 카드 고정 결과는 비교 대상을 바꾸지 않는다.

표 자체를 새 오버레이 카드로 저장하거나 A/B를 자동으로 함께 고정하지 않는다. 상세 연결은 동일한 자료·정의의 기존 통합 상세를 재사용한다.

본문은 공통 세로 스크롤을 사용한다. 열 머리글과 행 이름을 읽을 수 있게 두고 A/B 숫자는 오른쪽으로 정렬한다. 좁은 창과 Windows 배율에서는 열 너비 조정·줄바꿈·가로 스크롤을 조합하되 숫자·단위·부호를 잃지 않는다. 큰 고정 너비로 사용자의 창을 강제 확대하지 않는다.

A/B 구분과 차이는 색상에만 의존하지 않는다. 기본 글자 대비와 기존 한글 글꼴을 유지하고, 표의 접근성 정보에 항목명·A/B 대상·값·단위를 연결한다. 키보드로 후보 선택·표 이동·상세/고정을 사용할 수 있게 기존 Qt 컨트롤의 탐색을 활용한다. 이 원칙은 [Microsoft 글자 접근성 지침](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/accessible-text-requirements)과 [Qt 표 탐색 문서](https://doc.qt.io/qt-6/qtableview.html)를 참고한 설계 선택이다.

중요한 비교 이유와 오류는 화면에서 읽게 하고 툴팁은 보충 설명에만 사용한다. [Microsoft 툴팁 지침](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/tooltips)도 핵심 작업에 필요한 정보를 화면에 직접 두도록 권한다. 새로운 UI 프레임워크를 도입한다는 의미는 아니다.

## 11 데이터와 코드 구성

기존 WeaponService의 개별 정의·원본 검증·수치·자원 범위를 사용한다. 표시 문자열을 다시 파싱하지 않고 숫자·단위·해석 상태·출처를 보존한 비교용 자료를 만든다. 피해 최소/최대는 확인된 숫자를 각각 전달한다. 기존 상세가 최솟값·최댓값을 하나의 문장으로 표시하더라도 그 문장을 다시 잘라 계산하지 않는다.

계산은 문자열에서 만든 Decimal로 처리하고 float를 경유하지 않는다. [Python Decimal 문서](https://docs.python.org/3/library/decimal.html)는 십진 표현과 연산 정밀도·반올림을 별도로 다룬다. 이 프로젝트에서는 기존 숫자 길이·크기 제한을 이어받고 차이·백분율 변환에 필요한 자릿수를 확보한다. 기본 정밀도 28이나 고정 80이면 모든 지수 표기에 충분하다고 가정하지 않는다. 범위를 벗어나 정확히 계산할 수 없으면 계산 범위 상태로 남기고 부정확한 숫자를 게시하지 않는다.

비교 행은 표시 이름 대신 고정 필드 ID·자원 ID·비용 종류·단위로 연결한다. 동일 여부는 정확한 숫자로 판단한 뒤 표시 형식을 적용한다. 읽기 상태가 바뀐 값에 이전 number 속성이 남아 있어도 확정 상태가 아니면 계산에 사용하지 않는다.

기존 comparison.py는 패치/스냅샷 차이 기능이다. 두 무기 비교는 별도 weapon_comparison 모듈과 기존 worker의 요청으로 분리한다. Qt의 표 모델/뷰를 활용하고 별도 서버·웹 UI·실시간 게임 수집·상시 감시를 추가하지 않는다. 일반 무기의 기존 색인과 카드 설정을 재사용하며 비교를 위한 전체 재색인을 요구하지 않는다.

## 12 응답·목록·용량 처리

한 비교 응답에서 같은 자료의 A/B 정의·크기·필드를 확인한 뒤 원자적으로 반영한다. 서로 다른 요청에서 도착한 A와 B를 임의로 이어 붙이지 않는다. 요청은 화면 세대·스냅샷·순서 있는 A/B 정의·언어·표시 항목·자원 페이지·필요한 설정 세대에 묶는다. 화면 이탈·대상 변경·좌우 교환·언어 변경 후 도착한 응답은 버린다.

Qt는 연결을 끊어도 이미 대기열에 들어간 호출이 도착할 수 있다고 설명한다. 따라서 요청 식별 확인을 함께 사용한다. 이는 [Qt QObject 문서](https://doc.qt.io/qt-6/qobject.html#disconnect)를 참고한 프로젝트 처리 방침이다.

비교 시작·대상/언어 변경·필요한 추가 범위 요청 때 기존 작업 스레드에서 읽는다. 화면 그리기나 게임 창 추적 타이머가 비교 데이터를 다시 읽지 않는다. 추가 항목을 접고 펼칠 때 이미 읽은 정상 결과를 재사용할 수 있으면 다시 요청하지 않는다.

후보·자원 목록은 기존 기본 20개/최대 100개 조회 한도를 사용한다. 비교 응답은 핵심 식별 정보·고정 행·현재 자원 페이지를 64KiB 안으로 제한한다. 넘치는 목록은 이어 읽기로 제공하고 행을 조용히 삭제하지 않는다. 핵심 응답 자체가 제한을 넘으면 크기 제한 상태를 설명하고 기존 상세로 연결한다. 비교 응답에 전체 원문이나 긴 진단을 넣지 않는다.

자료 누락·삭제·용량 제한·재시도에서도 같은 선택을 재사용할 수 있는지 먼저 확인한다. 더 이상 존재하지 않는 자료는 다른 스냅샷으로 자동 대체하지 않는다. 요청과 페이지를 바꿀 때 표 위치만으로 대상을 식별하지 않는다.

## 13 개발 범위와 순서

이번 범위는 같은 자료·같은 실제 크기의 무기 두 개 선택, 기본 성능·피해 특성·자원별 차이, 미확정 안내, 기존 상세/기술 연결·개별 카드 고정, 이력과 늦은 응답 처리다. 일반 무기를 중심으로 완성하고 기존 서비스가 확정한 항목만 계산한다.

변이 결합 규칙·동적 비용 계산·암묵적 게임 기본값 확대·전투 시뮬레이션·자동 추천·다수 무기 순위·패치 전후 비교 확장·비교 전용 오버레이·비교 기록 영구 저장은 후속 범위로 둔다. 발사 간격의 원문 조회와 실제 DPS 계산은 구분한다.

개발 순서는 다음과 같다.

1. 개별 정의·크기·단위·정확한 숫자·행 상태를 보존하는 비교 모델을 만든다.
2. A/B 후보 검색·임시 선택/취소·확정·좌우 교환을 연결한다.
3. 한 표에 성능·피해 특성·자원별 값과 차이·공통 안내를 표시한다.
4. 같은 자료의 상세 왕복·요구 기술/상위 부품·개별 카드 고정을 연결한다.
5. 이력·언어·페이지·요청 세대·화면 크기 대응을 마무리한다.

## 14 구현 100% 이후의 필수 확인

기능 구현을 모두 마친 다음 아래 항목만 확인한다. 개발 중 제품 테스트·검수를 앞당기거나 통과하지 않은 결과를 완료로 기록하지 않는다.

- 실제 같은 크기 일반 무기 한 쌍의 선택 → 값/차이 확인 → 상세 왕복 → 원하는 카드 고정 흐름. 예: 같은 자료의 소형 청색 레이저와 소형 자외선 레이저.
- 피해 끝값 교차·퍼센트포인트·배율·전력 유형·반올림 전 작은 차이·정확한 0의 계산과 표현.
- 자료/크기 불일치·같은 정의·중복·선언 없음·조건 비용·변이 미확정에서 잘못된 차이를 만들지 않는지.
- 대상 변경 취소·확정·좌우 교환·언어 변경·뒤로 가기·늦은 응답·자원 페이지에서 이름과 값이 섞이지 않는지.
- 작은 창·배율·긴 이름/숫자·키보드 탐색과 안내 반복, 기존 카드 중복·좌표·한도 보존.
- 최종 실행 파일에서 위의 일반 무기 흐름을 한 번 이어서 확인.

완료 기준은 사용자가 같은 자료의 무기 두 개에서 얻고 잃는 기본 성능·피해 특성·비용을 읽고, 선택을 잃지 않은 채 상세와 카드를 사용할 수 있는 상태다. 커밋·푸시·PR·병합·배포는 별도 실행 범위다.
