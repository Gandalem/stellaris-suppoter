# 무기 부품 조회와 기술 연결 1안 초안

기술을 찾은 다음 해당 기술을 요구하는 무기와 기본 성능까지 이어서 볼 수 있게 한다. 첫 범위는 관리창의 무기 검색·상세와 기술 상세의 관련 무기 목록이다. 기존 기술 카드의 간결한 요약과 게임 입력 통과 동작은 유지한다.

## 1 사용 흐름

1. 청색 레이저 기술의 상세를 연다.
2. ‘이 기술을 요구하는 무기’에서 소형·중형·대형 등 개별 부품을 확인한다.
3. 부품을 선택해 기본 성능, 자원 비용, 요구 기술과 추가 조건을 읽는다.
4. 요구 기술을 선택하면 같은 자료의 기술 상세로 돌아간다.

직접 찾을 때는 새 ‘무기 검색’ 화면에서 한국어·영어 이름 또는 부품 ID를 사용한다. 기술과 부품은 조회 중인 같은 스냅샷으로 연결한다.

## 2 기술 상세의 관련 무기

목록에는 부품 이름, 슬롯 크기, 추가 조건 유무를 표시한다. 소형·중형·대형은 별개 정의로 유지하고 크기순으로 정렬한다. 이름이 같아도 ID나 정의가 다른 항목은 합치지 않는다. 직접 명시된 component_set은 묶음 표시를 돕는 정보로만 사용한다.

목록 제목은 ‘이 기술을 요구하는 무기’로 한다. prerequisites에 해당 기술 ID가 직접 적힌 관계를 연결한다. ‘지금 장착 가능’이나 ‘연구만 하면 모든 함선에서 사용 가능’으로 바꾸지 않는다. 다른 요구 기술이 함께 있으면 부품 상세에 모두 표시한다.

추가 조건이 있는 항목에는 ‘추가 조건’ 표시를 한 번 붙인다. 상세에서 조건 블록의 한국어 제목과 원문을 확인한다. 짧은 목록도 내부적으로 전체 관계를 보존하고, 기본 20개씩 더 보기를 제공한다. 자료 범위가 불완전하면 ‘연결 없음’으로 단정하지 않는다.

## 3 무기 검색과 상세

검색은 이름·정확한 ID, 슬롯 크기 필터를 제공한다. 계열 필터는 파일에 직접 명시된 등록 태그가 있는 경우에 사용한다. 파일 이름이나 피해 수치를 보고 레이저·미사일 등으로 추정하지 않는다. 중복 정의는 출처를 함께 보여주고 사용자가 선택한다.

상세는 아래 순서로 구성한다.

| 영역 | 표시 내용 |
|---|---|
| 제목 | 부품 이름, 슬롯 크기, 명시된 무기 계열 |
| 기본 성능 | 단발 피해 범위, 사거리, 기본 명중률·추적률, 전력 영향 |
| 피해 특성 | 선체·장갑·보호막 피해 배율과 관통 값 |
| 자원 | 제작에 필요한 자원과 유지비를 자원별로 구분 |
| 요구 사항 | 요구 기술 전체, 추가 사용·표시 조건 |
| 근거 | 선택한 표시값의 TXT·CSV·변수 정의와 원문 보기 |
| 접힌 기술 정보 | 부품 ID, 스냅샷, 파일 해시, 진단 |

기본값이 확인된 항목은 값만 표시한다. 값 없음·중복·수식은 해당 항목에서 구분하고, 다른 정상 항목은 계속 읽을 수 있게 한다. 설명이 있으면 명시된 연결 규칙으로 같은 자료의 번역을 사용한다.

정확한 단위가 등록된 수치만 변환한다. 명중률·추적률의 비율은 정확한 십진수로 백분율 표시하고, 피해 배율은 ×값으로 표시한다. 100%를 넘는 값을 임의로 잘라내지 않는다. 전력의 음수·양수는 보존해 ‘전력 영향’으로 보여준다. 발사 간격은 원문 단위가 확정된 경우에만 시간으로 표시하며, 그 외에는 근거 화면에 원래 값을 남긴다.

기본 성능은 설치 파일의 기준값이다. 제국 보정·함선 보정·상대 회피율을 적용한 실전 성능이나 승률은 계산하지 않는다.

## 4 이번에 읽을 자료

| 자료 | 역할 |
|---|---|
| common/component_templates 아래 TXT | weapon_component_template의 부품 ID·크기·요구 기술·자원·조건 |
| weapon_components.csv | 부품 ID별 기본 무기 수치 |
| mutation_weapon_components.csv | 명시된 부품 ID에 대응하는 별도 무기 수치 |
| common/scripted_variables와 파일 최상위 변수 | 자원·수치의 한 단계 숫자 참조 |
| 기존 기술·한영 번역 자료 | 요구 기술 상세, 이름과 설명 |

CSV는 위 두 파일만 명시적으로 포함한다. 다른 CSV나 다른 종류의 부품 정의를 파일 확장자만으로 무기 자료에 섞지 않는다. 변이 관련 CSV의 정적 행을 읽는 것과 플레이 중 선택된 변이를 계산하는 것은 구분한다.

기존 부품 adapter는 합성 문법의 component_template을 대상으로 한다. 실제 weapon_component_template은 등록된 별도 추출 경로로 추가하고 기존 합성 계약을 보존한다. 장갑·보호막·함재기·함선 설계·변이 적용 결과는 후속 범위다. 지정한 설치 폴더의 스냅샷을 사용하며 모드 로드 결과와 현재 세이브는 이번 범위에 넣지 않는다.

## 5 TXT와 CSV 수치를 연결하는 규칙

부품의 key와 CSV의 key를 원문 대소문자 그대로 정확히 연결한다. 번역 이름·비슷한 ID·component_set을 이용해 수치 행을 대신 선택하지 않는다.

현재 설치 파일에는 무기 수치 CSV가 TXT의 수치를 덮어쓴다는 안내가 있다. 지원하는 데이터 정책에 이를 명시하고, 동일 key의 단일 CSV 행에서 지원하는 숫자가 있는 필드는 해당 CSV 값을 사용한다. 원래 TXT 값도 근거에 남긴다. CSV 행 자체가 없고 해당 범위 전체를 읽은 경우에만 TXT의 직접 수치로 연결한다.

CSV 셀이 비어 있거나 해석할 수 없는 경우 TXT나 0으로 자동 대체하지 않는다. CSV에 남아 있는 cost 열은 현재 제작 자원 비용으로 사용하지 않는다. 제작 비용과 유지비는 TXT의 resources.cost와 resources.upkeep에서 읽는다.

중복 부품 정의, CSV의 중복 key·중복 열, 두 표의 같은 key 충돌은 첫 값이나 마지막 값으로 해결하지 않는다. 부품 정의 후보와 수치 후보를 분리해 표시한다. 불완전한 범위에서는 후보가 하나라는 이유만으로 우선순위를 확정하지 않는다.

숫자는 필드별 범위를 적용한다. 피해·사거리·자원 비용은 0 이상, 전력 영향은 부호 있는 값을 허용한다. 유한한 십진 리터럴과 한 단계 @변수만 처리하고, 연쇄 변수·산술식·조건 평가는 원문으로 남긴다. 기존 기술 비용 처리의 음수 금지 규칙을 무기 전력에 그대로 적용하지 않는다.

## 6 출처와 저장

TXT·CSV·변수 파일 모두 기존 파일 개수·크기·총량 한도 안에서 원본 해시와 함께 저장한다. CSV 헤더·논리 행·셀의 원래 위치를 보존하고, 숫자 표시에는 열 이름과 값의 출처를 연결한다. 단순 문자열 분리로 따옴표나 빈 셀의 위치를 잃지 않는다.

세미콜론 구분, 주석, BOM·줄바꿈, 빈 셀, 행 길이를 명시적으로 처리한다. 알 수 없는 열은 보존하고 원문에서 확인할 수 있게 한다. Python 표준 CSV 도구를 활용하되 출처 위치와 자원 한도는 앱에서 함께 관리한다. CSV 형식 추정이나 암묵적인 float 변환에 맡기지 않는다.

새 스냅샷에 부품·수치 표와 해석 정책을 포함한다. 파일별 산출물과 역방향 기술 관계를 저장해 상세를 열 때마다 전체 파일을 다시 읽지 않는다. TXT·CSV·변수·번역 중 바뀐 자료가 영향을 주는 결과를 갱신하고, 누락됐던 key의 추가와 중복 후보의 발생도 반영한다.

부품의 기술 요구 관계는 전용 관계로 저장한다. 기존 이벤트 참조로 기록하지 않는다. 기존 기술 답변·검색·비교 계약과 이전 스냅샷은 보존한다. 과거 자료에는 새로 설치된 부품 파일을 끼워 넣지 않고, 해당 자료에 부품 범위가 없음을 상세에서 한 번 알린다.

## 7 기존 화면과 오버레이 연결

관리창에 무기 검색을 추가하고 기술 상세에 관련 무기 목록을 넣는다. 부품 상세의 요구 기술도 같은 스냅샷으로 이동한다. 화면을 이동해도 검색어·선택 항목·스크롤 위치를 복원한다.

기술 카드의 기본 표시 항목이나 위치·크기는 자동 변경하지 않는다. 게임 위에서는 기존 검색·편집 모드의 상세 보기로 관련 무기에 접근한다. 부품 고정 카드, 카드 비교 창과 전체 기술 트리 그림은 첫 범위에 넣지 않는다.

기존 Qt 화면과 작업 스레드를 활용한다. 화면 추가로 기존 메뉴의 번호가 밀려 잘못 이동하지 않도록 탐색 연결도 함께 정리한다. 응답은 요청 번호·스냅샷·부품 정의·언어를 확인해 적용하고 이전 응답을 버린다. 게임 설명과 조건 원문은 일반 텍스트로 표시한다.

## 8 개발 순서

1. 실제 무기 정의와 CSV의 원문 위치를 보존하는 자료 모델을 연결한다.
2. 부품·수치·자원·번역의 증분 색인과 기술 역방향 관계를 저장한다.
3. 무기 검색과 기본값·근거 상세를 만든다.
4. 기술 상세와 부품 상세의 왕복 이동을 연결한다.
5. 기존 사용자 자료와 카드 동작을 보존한 채 새 자료 적용 흐름을 정리한다.

외부 서비스·새 UI 프레임워크·게임 메모리 접근을 추가하지 않는다. 실행 파일 생성과 Git 통합·배포는 별도 범위로 구분한다.

## 9 기능 작성 완료 후 필수 확인

모든 기능을 작성한 다음 아래 항목만 집중 확인한다.

- 청색 레이저 기술 → 실제 소형·중형·대형 부품 → 같은 자료의 요구 기술로 왕복 이동.
- TXT와 CSV의 연결·우선순위, 셀·숫자·자원 변수의 원문 위치 일치.
- 빈 값/0/음수 전력/중복/누락/수식과 추가 조건의 구분.
- CSV·변수 변경, 누락 key 추가·삭제와 이전 기술 카드 자료 보존.
- 긴 목록·한영 이름·과거 응답 폐기, 기존 오버레이 입력 통과와 화면 탐색에 영향이 없는지 확인.
