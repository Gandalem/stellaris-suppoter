# 단계별 로드맵

기간 약속이 아니라 **의존성과 통과 조건**으로 진행합니다. 기능 상태는 features.json을 기준으로 합니다.

| 단계 | 작업 | 통과 조건 | 사용자에게 보이는 결과 |
|---|---|---|---|
| M0: 문서 하네스 | 이번 부트스트랩 | 문서·원장 검사와 검사기 자체 회귀 통과 | 구현 범위·다음 작업·평가 기준 |
| M1: 첫 수직 슬라이스 | TASK-001~013 | 합성 기술 → 번역 → DB → 검색 → 출처 출력 end-to-end | 게임·모델 없이 검증 가능한 기술 검색 |
| M2: v0.1 preview | TASK-014~020 | 도메인 확장·관계·증분·안전·평가·패키지 통과 | 오프라인 로컬 정적 데이터 도우미 |
| M3: v0.1 검증 릴리스 | TASK-021~022 | 사용자 환경의 설치 데이터 read-only 스모크와 체크리스트 | 검증한 환경·게임 스냅샷이 명시된 릴리스 |
| M4: v0.2 | TASK-023~025 | 외부 최신성·모델 동의·근거·예산 회귀 | 공식 변경 기록 + 선택적 한국어 AI 설명 |
| M5: v0.3 | TASK-026~028 | 로드 규칙·효과 데이터·세이브 의미 검증 | 모드/현재 세이브를 구별한 분석 |
| M6: v0.4 | TASK-029~030 | 계산 교차검증·오차 표시·UI 보안 | 상황별 계산 및 로컬 UI |

M1 안에서도 한 번에 모두 구현하지 않습니다. 핵심 순서는 개발 환경 → 합성 corpus → 설정/목록 → lexer/parser → 기술/번역 → DB/검색 → 인용 → CLI입니다. 모듈 하나만 길게 만들지 않고 작은 합성 데이터를 끝까지 통과시키는 것을 먼저 확인합니다.

M2까지는 사용자 게임 파일이 없어도 개발을 진행할 수 있습니다. TASK-021은 실제 게임 데이터 없이는 끝낼 수 없으며, 막히면 preview 상태를 유지합니다. 실제 데이터 검증의 막힘을 이유로 fixture 회귀까지 중단하지 않습니다.

M4 이후는 처음부터 세부 구현을 확정하지 않습니다. 시작할 때 출처·호환성·사용자 동의를 재확인하고 해당 작업을 더 작게 나눕니다. 벡터 검색, 모델 학습, 서비스 배포는 정확성이나 사용자 가치가 측정으로 입증될 때만 추가합니다.
