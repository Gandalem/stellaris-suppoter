# 기술 카드 정보 개선 — 2안

1안을 시니어 개발자·기술 기획자·스텔라리스 플레이어 관점에서 다시 검토한 안이다. 게임 중 빠르게 읽는 요약 카드와 근거를 확인하는 관리창 상세를 나누고, 표시 가능한 값의 범위와 기존 카드 전환 절차를 확정한다. 2026-10-25 사용자가 이 안의 개발을 승인했다. [1안](TECH-CARD-INFO-OPTION-1.md)은 비교 자료로 보존한다.

## 1. 재검토에서 바꾼 결정

| 1안에서 보완할 점 | 2안의 결정 |
|---|---|
| 숫자가 나오면 실제 제국의 비용처럼 보일 수 있음 | 기본 연구 비용이라는 명칭과 기본 게임 파일 기준을 함께 표시 |
| 선행 기술 목록이 전체 연구 조건처럼 보일 수 있음 | 선행 목록과 실제 연구 가능 판정을 구분하고 보유·가능 체크를 만들지 않음 |
| 기본 카드에 설명과 경고가 다시 쌓일 가능성 | 설명은 기본 꺼짐, 정상 수치에 상태 태그를 붙이지 않음 |
| 작은 카드에서 선택한 정보가 조용히 사라질 수 있음 | 줄 수 제한과 추가 항목 표시, 상세 화면으로 연결; 카드 안 스크롤 제거 |
| 변수의 범위·중복·정의 위치 처리가 모호함 | 단일 숫자 정의만 허용하고 두 범위가 충돌하면 해석을 보류 |
| 전체 자료가 partial이면 모든 값이 불명확해 보임 | 자료 범위와 개별 필드의 확인 상태를 따로 관리 |
| 표시 항목 편집에 cost 같은 내부 키 입력이 필요함 | 한국어 체크박스와 순서 선택을 사용하고 기존 내부 키는 유지 |
| 갱신하면 이미 있는 카드와 중복될 수 있음 | 적용 전에 카드 정체성을 비교하고 자동 병합·삭제하지 않음 |
| 늦게 도착한 응답이 갱신한 카드에 덮일 수 있음 | 요청 ID와 UID·스냅샷·정의·언어가 맞는 응답만 반영 |
| 다른 실행 환경의 색인을 사용자 완료로 오인할 수 있음 | 실제 앱의 저장소와 활성 자료를 기준으로 첫 적용 완료를 확인 |

## 2. 사용자가 보는 기본 카드

```text
청색 레이저
물리학 · 1단계

기본 연구 비용   1,250
선행 기술        적색 레이저

기본 게임 파일 기준
```

예시는 설치 파일에서 확인한 기술/변수 정의의 기본값을 사용했다. 현재 제국의 최종 비용, 연구 완료 시간이나 실제 연구 가능 여부를 계산한 결과는 아니다.

### 기본으로 보이는 정보

- 기술명: 선택 언어의 확인된 이름 → 영어 → ID 순서로 대체한다. 이름은 제목에 한 번만 표시한다.
- 분야와 기술 단계: 물리학/사회학/공학 등으로 표시한다. 단계 0을 누락으로 처리하지 않고, 현재 연구 횟수나 진행 레벨로 해석하지 않는다.
- 기본 연구 비용: 확인된 숫자만 보여준다. 0과 값 없음은 분리한다.
- 선행 기술: 같은 스냅샷에서 확인한 이름을 보여준다. 목록은 연구 완료 여부나 전체 연구 조건을 뜻하지 않는다.
- 데이터 기준: 기본 게임 파일 기준을 작게 표시한다. 고정한 카드가 새 자료로 자동 전환되지는 않는다.

분류와 기술 설명은 선택 항목이다. 설명은 기본으로 끄고, 사용자가 켜면 확인된 게임 설명을 최대 2줄까지 보여준다. 희귀·위험 표시는 해당 기술 정의에 직접 명시된 단일 플래그를 확인한 경우에만 짧은 텍스트로 표시한다. 색상만으로 의미를 전달하지 않는다. 플래그가 없다는 이유로 반대 상태를 추정하지 않는다.

기술 효과, 부품 성능, 전략 평가를 설명에서 새로 만들어내지 않는다. 예를 들어 modifier 블록이나 technology_swap이 있다는 것만으로 현재 제국의 최종 효과나 선택되는 대체 기술을 확정하지 않는다. 이러한 원문은 상세에서 확인할 수 있다.

### 상태를 보여주는 방식

| 항목 상태 | 기본 카드 표시 |
|---|---|
| 값과 출처 확인 | 값만 표시 |
| 선행 기술 없음이 확인됨 | 없음 |
| 변수 정의 없음 | 값 확인 필요 |
| 여러 정의·범위 충돌 | 값 확인 필요; 상세에서 충돌 후보 표시 |
| 수식·동적 표현 | 원문 확인 필요 |
| 과거 자료에 필요한 변수 파일이 없음 | 변수 자료 없음 |
| 선택하지 않은 설명·분류 | 자리를 비워두고 경고를 만들지 않음 |

자료 전체의 부분 분석은 데이터 기준 옆의 짧은 표시 한 곳으로 알리고, 상세에서 범위를 설명한다. 개별 필드에서 확인한 값은 그대로 읽을 수 있게 한다. 확인하지 못한 값을 0이나 임의의 숫자로 대신하지 않는다. 출처 불일치·손상 오류는 정상값으로 유지하지 않고 오류로 전환한다.

## 3. 카드 크기와 표시 규칙

새 카드 기본 크기는 96-DPI 기준 360×260으로 잡는다. 기존 카드의 좌표·크기·불투명도는 자동 변경하지 않는다.

- 제목은 최대 2줄로 줄바꿈한다. 화면에 다 보이지 않는 이름은 생략 표시하고 상세에서 전체 이름을 제공한다.
- 일반 크기에서는 이름 → 분야/단계 → 기본 비용 → 선행 기술 순서로 보인다.
- 기본 선행 목록은 최대 3개 항목까지, 각 항목은 최대 2줄까지 허용한다. 나머지는 ‘외 N개’로 표시한다. ‘없음’은 목록이 완전한 경우에만 사용한다.
- 작은 카드에서는 설명·분류부터 접고, 더 작으면 선행 목록을 개수 요약으로 줄인다. 접은 항목이 있음을 ‘추가 N항목’으로 알린다. 중요한 항목의 누락을 빈칸처럼 보이게 하지 않는다.
- 요약 카드 안에는 스크롤바를 두지 않는다. 전체 내용은 관리창 상세에서 스크롤해 읽는다. 카드 보기 상태에서는 스크롤 입력도 게임으로 전달한다.
- 긴 내용이나 비동기 응답이 와도 카드 크기를 갑자기 바꾸지 않는다. 사용자가 편집 모드에서 조절한 크기를 유지한다.
- 한글·숫자·어두운 배경의 대비와 윈도우 배율을 고려한다. 글꼴 파일을 임의로 복제해 배포하지 않는다.

중요한 정보는 hover나 툴팁에만 두지 않는다. 입력 통과 상태에서는 마우스 hover 자체를 받지 않을 수 있기 때문이다.

## 4. 보기·편집 동작

| 상태 | 동작 |
|---|---|
| 카드 보기 | 요약만 표시, 게임 클릭·드래그·키 입력 통과 |
| 검색·편집 | ‘편집 중’ 표시, 제목 드래그·크기 조절·상세/관리 조작 가능 |
| 숨김 | 카드와 편집 창 모두 숨김 |

검색·편집 모드의 빠른 동작은 ‘상세 보기’와 ‘카드 관리’ 두 개를 기본으로 한다. 상세 보기는 해당 카드의 데이터 기준을 고정한 채 관리창의 기술 상세로 이동한다. 카드 관리는 해당 UID의 항목을 선택해 표시 항목·제거·중복 정리로 연결한다. 카드 보기에서는 이 버튼들을 숨기고 입력을 가로채지 않는다.

선행 기술의 전체 목록과 탐색은 상세 화면에서 기존 참조 조회를 사용한다. 다른 정의를 선택하거나 새 카드를 고정하는 동작도 같은 스냅샷 안에서 시작한다. 이름이 같은 서로 다른 ID나 같은 ID의 여러 정의를 하나로 합치지 않는다.

표시 항목은 한국어 체크박스로 선택한다. 분야·단계·분류·기본 비용·선행 기술·기술 설명을 제공하고, 저장은 기존 area/tier/category/cost/prerequisites 등의 내부 키를 유지한다. 기존 사용자 설정의 알 수 없는 키는 삭제하지 않고 기타 항목으로 보존한다. 표시 항목을 바꿔도 원문 데이터는 변경하지 않는다.

## 5. 정적 기본값 처리의 확정 범위

비용은 일반적인 십진 정수·소수와 @변수의 한 단계 참조만 처리한다. 비용은 0 이상이고 유한해야 한다. 숫자 표현은 최대 64자로 제한하며, 지수 표기·산술식·연쇄 변수·조건 평가는 이번 범위에서 제외한다. 소수는 Decimal 등 정확한 십진 표현으로 보존하고 임의 반올림하지 않는다.

### 변수 후보 선택

1. 기술 파일의 최상위 선행 숫자 정의와 common/scripted_variables의 정의를 같은 스냅샷 안에서 수집한다. 주석·문자열·중첩 조건 블록을 변수 선언으로 해석하지 않는다. 변수 식별자는 원문의 철자와 대소문자를 유지하고 검색용 이름 정규화·번역 규칙을 적용하지 않는다.
2. 단일 유효 후보만 있고 해당 정의 범위를 완전히 확인한 경우에 숫자로 연결한다.
3. 로컬과 공통 정의가 동시에 맞거나 같은 범위에 선언이 여러 개이면, 동일한 숫자여도 임의 우선순위로 선택하지 않는다. 충돌로 남긴다.
4. 기술 필드 자체가 중복돼도 첫 값이나 마지막 값을 택하지 않는다.
5. 파일 또는 범위가 불완전해 다른 후보의 존재를 배제할 수 없으면 단일 정의라고 확정하지 않는다.

변수 충돌 후보를 사용자가 임의 선택해 확정 비용으로 바꾸는 동작은 제공하지 않는다. 기존의 기술 정의 후보 선택과는 구분한다.

이 보수적인 범위에서 처리하지 못한 항목은 다른 정상 필드와 분리해 표시한다. 일부 항목 때문에 기술 카드 전체를 빈 화면으로 만들지 않는다.

1,250이라는 표시의 근거는 cost 필드 → @변수 참조 → 숫자 정의로 이어진다. 직접 리터럴이면 cost 값의 원문이 근거다. 원래 표현식, 숫자, 상태, 각 SourceRef를 함께 보관한다. 변수만 존재하는 기술 파일도 출처 수집에서 누락하지 않는다.

## 6. 상세 화면

상세는 동일한 카드 표시 데이터를 재사용하며 별도 계산 규칙을 만들지 않는다. 다음 순서로 구성한다.

1. **읽기 쉬운 기술 정보:** 이름, 분야/단계/분류, 기본 비용, 전체 선행 목록, 선택적 게임 설명.
2. **값의 근거:** 표시값, 원래 표현식, 선택한 변수 정의, 참조 관계, 누락/충돌/미지원 사유.
3. **원문·데이터 기준:** 파일·줄 위치, 원문 보기, 번역 대체, 자료 분석 범위.
4. **기술 정보:** ID, 스냅샷, 해시, 진단 코드. 기본으로 접는다.

기술 설명은 명시적 연결 또는 해당 버전에서 근거가 확인된 설명 키가 같은 스냅샷에 있을 때만 사용한다. 문자열 이름이 비슷하거나 검색에서 함께 나왔다는 이유로 연결하지 않는다. 정적 번역 참조만 확장하고, 동적/서식 표현을 임의로 지워 정상 설명으로 만들지 않는다. 요약에 표시할 수 없는 설명은 상세에서 원문과 상태를 유지한다.

게임 텍스트는 일반 텍스트로 표시한다. 링크 동작은 SourceRef·선택한 기술 식별자에 연결한 앱 동작으로 구현하며, 게임 문자열의 HTML·외부 URL·명령을 실행하지 않는다.

## 7. 저장·갱신과 응답 일관성

### 변수 수집과 재사용

- 변수 파일도 파일 목록·원문 캐시·해시·스냅샷 정체성에 포함한다. 지원 경로만 읽고 기존 파일/총량/자원 한도를 유지한다.
- 기술 파일의 기존 파서·AST·출처를 재사용하고, 수집 단계에서 같은 파일을 변수용으로 별도 중복 파싱하는 구조를 피한다.
- 변수 해석 정책 버전을 기록한다. 기술 필드, 변수 후보/범위, 내용·완전성에 의존하는 결과만 캐시한다.
- 누락 조회도 의존관계에 기록한다. 이후 변수가 추가되거나 충돌 후보가 생기면 결과를 갱신한다.
- 줄 위치만 바뀌었을 때 값 재사용 여부와 출처 재결합을 구별한다. 예전 출처를 새 카드에 붙이지 않는다.
- 카드가 표시될 때마다 전체 번역/변수 파일을 다시 읽지 않는다. 기존 작업 스레드와 파일별 결과·메모리 한도를 활용한다.

### 표시 데이터

기존 AnswerFact의 원문·SourceRef는 유지하고, 카드용 구조에 표시값·개별 상태·근거를 별도로 연결한다. 숫자를 해석했다고 기술 전체나 데이터 전체가 완전한 것으로 승격하지 않는다. 기존 CLI·검색·참조·비교 카드의 계약을 일괄 변경하지 않는다. 우선 기술 카드와 기술 상세에 적용한다.

하나의 카드 응답은 동일 스냅샷·정의·언어로 완성된 뒤 한 번에 반영한다. 기존 요청 ID에 더해 현재 UID/스냅샷/정의/언어와 맞는지 확인한다. 삭제·갱신·언어 변경 후 도착한 과거 응답은 버린다. 불완전한 중간 결과로 기존 카드를 잠깐 비우거나 최신/과거 정보를 섞지 않는다.

## 8. 첫 적용과 기존 카드 갱신

1. 사용자 앱이 실제로 읽는 저장소와 활성 자료를 확인한다. 다른 실행 환경에서 같은 경로에 색인이 있다는 이유로 완료 처리하지 않는다.
2. 앱에서 변수 파일을 포함해 한 번 색인한다. 부분 사용 동의·취소·실패·활성화는 기존 흐름을 따른다.
3. 새 카드는 새 자료로 만든다. 기존 카드는 원래 스냅샷을 유지한다.
4. 기존 카드의 갱신 화면에서 이름·기본 비용·선행 기술의 전후 차이를 보여준다. 적용은 사용자 선택으로 한다.
5. 갱신할 때 UID·위치·크기·불투명도·표시 항목을 유지한다. 같은 새 정의의 카드가 이미 있으면 중복 갱신을 적용하지 않고 기존 새 카드 선택 또는 취소를 제공한다. 이전 카드를 자동 삭제하거나 합치지 않는다.

과거 스냅샷에 변수 출처가 없으면 현재 설치 파일에서 가져와 메우지 않는다. 카드의 현재/과거 여부는 선택한 자료와의 관계로 설명하고, 실제 게임 버전이나 최신 패치임을 추정하지 않는다. 여러 카드의 일괄 갱신은 이번 범위에 넣지 않는다.

## 9. 개발 범위와 순서

**포함:** 기술 요약 카드, 한국어 항목 선택, 한 단계 정적 기본값, 확인된 선행 이름, 선택적 설명·직접 명시 플래그, 상세/출처/관리 연결, 기존 카드 전환과 중복 방지.

**후속:** 제국/세이브 기반 실제 비용·완료 시간·연구 가능 판정, 등장 확률·가중치 계산, 모드 적용 결과, 부품 성능·효과 추론, 기술 트리 그림·연구 경로 추천, 카드 일괄 갱신, 전체 앱 디자인 개편.

구현 순서는 자료/해석 정책 → 표시 데이터 → 요약 카드 → 상세·관리 동작 → 기존 카드 전환이다. 새 외부 서비스나 AI·새 UI 프레임워크는 추가하지 않는다.

### 구현 100% 이후 필수 확인

- 청색 레이저의 기본 비용·분야/단계·선행 기술 이름과 각각의 실제 출처 연결.
- 0/누락/중복 필드·변수/범위 충돌/불완전 파일/수식의 구분. 조건이나 보유 상태를 만들어내지 않는지 확인.
- 변수 추가·변경·삭제와 누락/충돌 변화, 이전 스냅샷 카드 보존, 갱신 충돌과 늦은 응답 폐기.
- 작은 카드·긴 이름·선행 다수·한국어/영어·DPI에서 표시 누락 안내와 입력 통과 확인. 미리보기의 글꼴을 먼저 준비하고 glyph 누락이 있는 이미지는 통과로 보지 않음.
- 사용자 앱에서 색인→부분 동의→기존 카드 갱신→표시를 확인. 검사 프로세스와 실제 사용자 앱 결과를 구별해 기록.

중간에 검수를 반복하는 대신 해당 수정 기능의 작성을 끝낸 뒤 위 필수 항목만 확인한다. 실제 완료 내용과 남은 범위를 간결하게 보고하고, 커밋·푸시·PR·병합·배포는 별도 실행 범위로 유지한다.
