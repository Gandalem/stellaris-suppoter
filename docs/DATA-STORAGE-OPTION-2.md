# 로컬 데이터 저장 2안

사용자 승인된 구현 범위는 파일별 번역 영구 저장, 배치 처리, 반복 진단 집계, 현재 게임 lexical 문법, 검색 투영 영구 저장, 키/언어/누락 의존관계 갱신, 별도 색인 worker, 스냅샷 및 구버전 카드 보존이다.

원문은 기존 content-addressed cache에 보존한다. 파일 결과는 파일 정체성+내용 해시+파서 버전으로 식별하고 같은 결과를 스냅샷 사이에서 공유한다. 별도 SQLite 카탈로그의 batch는 1000항목 또는 8MiB 먼저 도달 시 기록한다. 디스크는 2GiB/전체 번역 row 200만, 파일/총 입력/파일별 레코드/참조 깊이·방문 수 한도는 유지한다. 경고 샘플은 코드·심각도별 최초 3개, 전체 발생 횟수는 별도 저장한다. hard limit/인코딩 손상은 활성화하지 않는다.

resolver는 DB에서 키를 조회하고 실패한 조회도 파생 결과 의존관계에 포함한다. 파일 해시가 달라도 값과 후보 구성이 같으면 결과를 재사용하면서 출처를 현재 스냅샷으로 재결합한다. 표시 언어 변경은 이미 저장된 두 언어 데이터를 이용한다. 중복·순환·미지원 표현은 원문/상태를 보존하고 선택 범위가 불완전한 경우 단정하지 않는다.

기존 snapshots.sqlite3는 유지하며 새 정책은 localisation_storage=localisation-disk-2로 구분한다. 새 카탈로그의 불변 파일 결과 manifest receipt를 기존 DB에 연결한다. 기존 API용 투영은 참조된 번역과 기술만 포함하지만 전체 원문/번역 기록은 카탈로그에 보존한다. 기존 스냅샷은 이전 reader로 읽는다. 변경 비교는 새로운 카탈로그를 정렬된 키 그룹으로 스트리밍하고 결과 페이지의 크기를 제한한다. 불완전한 소스에서 추가/삭제를 단정하지 않는다.

검색용 DB는 별도 파일에 보존하고 authoritative 스냅샷 행의 fingerprint와 생성된 DB의 hash/size가 맞을 때 재사용한다. 손상/버전 차이 시 재생성한다. source/alias 검증 및 원본 span 대조는 기존 서비스를 유지한다.

색인 시 OS 파일 lock으로 단일 writer를 보장한다. 파일별 완료 결과만 재사용하며 실패/취소 job은 비활성이다. 완료 스냅샷은 원본 목록/내용 재확인 후 CAS로 전환한다. v2의 비활성 실패 staging만 제거하여 같은 입력으로 재시도할 수 있다. 검색/색인 각각의 worker와 DB 연결은 공유하지 않고 종료 시 둘 다 정리한다.

기능 코드를 모두 작성한 뒤 실제 설치 입력/한영 검색·출처/증분·삭제·누락·중복/재시작·영구투영/취소·실패복구/기존 API 회귀의 필수 검사만 실행한다. 커밋·푸시·PR·병합·배포는 별도 요청이다.
