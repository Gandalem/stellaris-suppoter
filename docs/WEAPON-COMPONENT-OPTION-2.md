# 무기 부품 조회와 기술 연결 2안 초안

기술을 연구했을 때 어떤 무기로 이어지는지, 원하는 슬롯의 부품은 무엇을 요구하는지 빠르게 찾는 화면을 만든다. 관리창의 무기 검색·부품 상세·기술과의 왕복 이동을 첫 범위로 한다. [1안](WEAPON-COMPONENT-OPTION-1.md)은 비교 자료로 보존한다.

## 1 재검토에서 바꾼 결정

| 1안의 보완점 | 2안의 결정 |
|---|---|
| 크기마다 같은 계열이 반복돼 목록이 길어짐 | 근거 있는 부품 계열로 묶고 소형·중형·대형 등 실제 정의를 펼쳐 선택 |
| 요구 기술이 있으면 바로 사용할 수 있는 무기로 오해할 수 있음 | 요구 기술·설계 조건·기술 화면 표시 조건을 구분 |
| 피해 범위만으로 모든 무기의 성능을 설명하기 어려움 | 최소/최대 사거리와 특수 작용 유무를 함께 읽고 기본 피해로 명칭 통일 |
| 전력의 음수 표기가 게이머에게 불편함 | 확인된 부호 규칙으로 소비/공급을 구분하고 원래 값 보존 |
| 같은 열을 가진 CSV 두 개에 같은 우선순위를 가정함 | 표의 역할과 필드별 우선순위를 각각 등록하고 근거 없는 합산·대체 금지 |
| 수치 하나의 근거를 찾으려고 긴 출처 목록을 뒤져야 함 | 선택한 항목에서 해당 값의 TXT·CSV·변수·단위 근거를 바로 열기 |
| 새로운 색인 뒤에도 이전 조회 자료가 남는 혼선 | 새 색인 적용 후 조회 자료 선택을 명확히 하고 과거 카드는 별도로 유지 |
| 기존 부품 코드가 실제 파일도 바로 처리한다고 보기 쉬움 | 실제 무기 wrapper·저장·검색·관계 reader까지 함께 확장 |

## 2 게이머의 기본 사용 흐름

청색 레이저 기술 상세에서 ‘이 기술을 요구하는 무기’를 연다. 계열을 펼쳐 원하는 크기를 선택하고 기본 성능과 추가 조건을 읽는다. 요구 기술을 누르면 같은 자료의 기술 상세로 돌아간다.

직접 찾을 때는 ‘무기 검색’을 사용한다. 한국어·영어 이름 또는 부품 ID로 찾고 슬롯 크기와 명시된 계열 태그로 좁힌다. 결과에는 이름·크기·추가 조건 표시가 먼저 보이고, ID와 파일 위치는 동명 정의를 구분할 때 보조 정보로 사용한다.

뒤로 가기는 검색어·필터·선택 행·펼친 계열·스크롤을 복원한다. 큰 팝업을 계속 쌓지 않고 관리창의 상세 영역에서 이동한다. 새 화면을 열어도 게임 위 기술 카드의 위치와 표시 항목은 유지한다.

## 3 관련 무기 목록과 계열

기술 연결은 부품의 prerequisites에 직접 적힌 정확한 기술 ID를 사용한다. 여러 기술이 있으면 명시된 목록을 모두 보존한다. 중복 블록·동적 참조가 섞인 경우 목록의 완전성을 따로 기록한다. 기술이 없다는 이유만으로 기본 지급·즉시 사용 가능으로 분류하지 않는다.

같은 component_set 참조가 단일 계열 정의로 확인될 때만 시각적으로 묶는다. 계열 이름과 등록 플래그는 같은 스냅샷의 component_sets에서 읽는다. 이름·ID 접두사·같은 피해 수치만으로 묶지 않는다. 계열 정의가 없거나 중복되면 개별 부품으로 표시한다.

묶음은 표시 방식이며 부품 ID·정의·수치·조건은 개별로 유지한다. 소형·중형·대형 등 크기순으로 정렬하고, 같은 크기의 별도 정의도 합치지 않는다. 우주생물 관련 플래그가 직접 명시돼 있으면 해당 계열을 구분하되, 플래그 부재로 일반 함선 전용을 추정하지 않는다.

기본 20개 묶음 또는 개별 항목씩 더 보기를 제공한다. 펼친 묶음의 자식도 제한된 배치로 읽는다. 총계가 완전한 경우에만 전체 개수를 표시하고, 부분 자료는 읽은 범위의 목록으로 안내한다. 필터를 바꾸거나 과거로 이동하면 그 조회 조건에 맞는 페이지를 사용한다.

## 4 부품 상세의 정보 순서

| 영역 | 표시할 내용 |
|---|---|
| 제목 | 이름, 슬롯 크기, 명시된 무기 계열과 자료 기준 |
| 기본 성능 | 기본 피해 범위, 최소/최대 사거리, 기본 명중률·추적률, 소비/공급 전력 |
| 피해 특성 | 선체·장갑·보호막 피해 배율, 장갑·보호막 관통 비율 |
| 자원 | 제작 비용과 유지비를 자원별로 표시 |
| 요구 사항 | 요구 기술, 설계·호환 조건, 기술 화면 표시 조건 |
| 이동 | 요구 기술로 이동, 직접 명시된 상위 부품으로 이동, 뒤로 가기 |
| 상세 근거 | 선택한 값의 원래 표현, 적용 규칙, 출처와 원문 |
| 접힌 기술 정보 | 부품 ID, 스냅샷, 파일 해시, 진단 |

기본 피해는 설치 자료의 기준값이다. 제국·함선 보정, 상대 회피, 실전 DPS와 승률은 계산하지 않는다. on_hit·연쇄 피해·범위 피해·크기 의존 효과 등이 있으면 ‘특수 작용’으로 한 번 알리고 세부 원문을 펼쳐 읽는다. 일반 피해 표에 효과를 임의로 더하지 않는다.

공격 가능한 최소 거리와 최대 거리는 별도 필드다. 최소 거리 정의가 없으면 0으로 채우지 않는다. 피해나 거리의 최소값이 최대값보다 크면 순서를 바꿔 정상 범위처럼 표시하지 않는다.

전력 부호 규칙은 설치 자료의 설명과 연결한다. 음수는 소비 전력, 양수는 공급 전력으로 표시하고 0은 전력 변화 없음으로 구분한다. 원래 부호는 근거에 남기며 장착 후 함선 잔여 전력을 계산하지 않는다.

명중률·추적률·관통 비율은 등록된 단위 규칙으로 백분율 표시하고 피해 배율은 ×값으로 표시한다. 임의로 100%를 상한으로 자르지 않는다. 소수는 정확한 십진 표현을 사용하고 단위 변환에서도 원문의 유효 숫자를 잃지 않는다. 발사 간격·준비 시간은 단위 근거가 있는 항목만 일반 시간으로 바꾸고 나머지는 상세 근거에서 원래 값을 읽는다.

상위 부품 이동은 단일 upgrades_to가 같은 자료의 부품 정의로 확인될 때 제공한다. 대상이 없거나 여러 정의이면 그 상태와 후보를 보여준다. 연속된 기술 ID나 이름으로 다음 단계를 만들지 않는다. 별도 비교 화면·자동 추천·상하위 연쇄 탐색은 첫 범위에 추가하지 않는다.

## 5 조건을 설명하는 방식

요구 기술, 부품이 설계 목록에 나타나는 조건, 다른 부품과의 호환 조건, 기술 화면에서 해금 항목을 표시하는 조건을 구분한다. potential·possible·slot_restriction·show_tech_unlock_if 등 원래 필드와 문맥을 보존한다. 등록되지 않은 조건 필드는 원래 이름으로 상세에 남긴다.

‘추가 조건’은 존재를 알리는 표시다. 현재 제국·함선에 대한 충족 판정이나 설치·활성 DLC 판정으로 사용하지 않는다. 조건이 있다는 이유만으로 기본 목록에서 숨기지 않는다. 다수의 무기에 조건이 있더라도 동일 경고를 문장마다 반복하지 않는다.

inline_script나 다른 외부 구문이 값을 주입할 수 있는 범위는 펼쳐 평가하지 않는다. 직접 읽은 선언과 합성 결과의 완전성을 구분한다. resources 안의 동적 비용 때문에 기본 피해까지 빈칸으로 만들지 않으며, 반대로 직접 숫자 하나가 있다고 동적 비용 전체를 확정하지 않는다.

설치 파일의 기본 정의를 읽으며 모드 로드 순서·현재 세이브·실제 연구 보유 상태는 적용하지 않는다.

## 6 읽을 자료와 수치 연결

| 자료 | 역할 |
|---|---|
| common/component_templates의 TXT | 실제 weapon_component_template, 요구 기술·자원·조건·상위 부품 |
| common/component_sets의 TXT | 단일 계열 정의, 계열 이름 연결과 직접 명시 플래그 |
| weapon_components.csv | 등록된 일반 무기 수치 표 |
| mutation_weapon_components.csv | 별도로 역할을 관리하는 변이 관련 수치 표 |
| common/scripted_variables와 파일 최상위 변수 | TXT 수치·자원의 한 단계 숫자 참조 |
| 기존 기술·한영 번역 | 요구 기술 상세와 이름·명시적 설명 |

다른 부품 wrapper·임의의 CSV는 자동으로 지원 범위에 넣지 않는다. 장갑·보호막·함재기, 변이 적용 결과, 함선 설계 계산과 부품 고정 카드는 후속 범위다. 변이 관련 표를 읽는 것과 실제 선택된 변이를 적용하는 것은 구분한다.

### 정의와 표의 결합

부품 key와 표의 key는 원문 대소문자를 유지해 정확히 연결한다. 묶음 ID·번역 이름·크기 접미사로 수치를 복사하지 않는다. 같은 key의 여러 정의·행·표가 있으면 각각의 후보와 출처를 유지한다. 같은 숫자여도 임의로 하나를 고르지 않는다.

일반 무기 표가 해당 TXT 수치에 우선한다는 근거를 지원 정책에 등록한다. 변이 관련 표는 헤더가 같다는 이유만으로 동일한 엔진 우선순위를 적용하지 않는다. 표별 대상·필드 우선순위의 근거가 확보된 범위만 기본 표시값으로 연결하고, 결합 규칙 밖의 선언은 상세에 각각 보존한다.

CSV 행이 없다는 것을 전체 지원 표 범위에서 확인한 경우에만 TXT의 직접 수치로 연결한다. 빈 셀·해석 불가 셀·중복 행을 ‘행 없음’으로 취급해 TXT로 넘어가지 않는다. 표가 없거나 범위를 읽지 못했을 때도 우선순위가 확정된 값처럼 표시하지 않는다.

CSV cost 열은 제작 자원 비용으로 사용하지 않는다. 제작 비용은 TXT resources.cost, 유지비는 resources.upkeep의 자원별 선언을 사용한다. 같은 자원이 중복되거나 여러 resources 블록이 충돌하면 합산하거나 마지막 값을 선택하지 않는다. 선언이 없다는 사실도 유지비 0을 뜻하지 않는다.

### 숫자와 변수 범위

CSV 셀은 직접 십진 숫자를 지원하고, TXT는 직접 숫자와 한 단계 @변수를 지원한다. CSV의 @표현을 연결된 TXT 파일의 로컬 변수로 임의 해석하지 않는다.

숫자 원문은 최대 64자이며 유한해야 한다. 피해·거리·비용은 0 이상, 전력은 부호를 허용한다. 비율·배율은 필드별 등록 범위를 적용하고 수식·지수 표기·연쇄 변수는 계산하지 않는다. 단위 변환의 십진 정밀도는 이 원문 범위를 보존하도록 정한다.

TXT 로컬 변수는 해당 파일의 기술/부품 정의보다 앞선 최상위 선언을 대상으로 한다. 파일과 공통 범위의 충돌·중복 선언·불완전 범위는 단일 정의로 확정하지 않는다. 선택된 값에는 필드 → 변수 참조 → 숫자 정의의 출처를 함께 연결한다.

## 7 화면 상태와 출처

정상값은 값만 표시한다. 값 없음·중복·미지원 식은 해당 필드에서 짧게 구분하고, 자료 전체의 부분 범위는 상세의 기준 표시 한 곳에 둔다. 출처 손상은 부분 자료와 구분해 실패로 전환하며 이전 정상값을 계속 보여주지 않는다.

숫자나 자원 항목을 선택하면 해당 항목의 근거를 바로 연다. TXT 선언, CSV 열 이름과 셀, 변수 정의, 단위 규칙이 연결된 순서로 보인다. 긴 전체 출처 목록의 앞부분에 밀려 선택한 숫자의 근거가 잘리지 않게 한다.

출처에는 스냅샷·원본 SHA·파일·논리 행/열·바이트 위치를 보존한다. CSV 디코딩 후의 값과 따옴표를 포함한 원문을 함께 유지하고, 셀이 실제로 그 부품 key의 행과 해당 헤더에 속하는지 확인한다. 원문 보기는 검증한 SourceRef를 사용하며 게임 문자열의 HTML·외부 URL·명령을 실행하지 않는다.

단위·우선순위 근거로 쓰는 설치 자료의 설명도 같은 스냅샷에 포함한다. 이름과 설명은 선택 언어 → 영어 → ID 순서로 대체하며, 무기 설명을 비슷한 번역 key에서 만들어 연결하지 않는다.

## 8 새 자료 적용과 과거 카드

홈의 기존 색인/변경 반영으로 부품 자료를 추가한다. 조회 자료가 기술·무기 정의·무기 수치·계열 중 어느 범위를 포함하는지 기록하고 화면에는 이해할 수 있는 자료 기준을 표시한다. 과거 자료의 ‘부품 범위 없음’과 새 자료에서 실제 연결이 없는 상태를 구분한다.

명시적으로 실행한 색인이 성공하면 새 검색은 새 자료로 시작하도록 연결한다. 작업 중 사용자가 과거 자료를 따로 선택했다면 그 선택을 유지하고 ‘새 자료로 보기’를 제공한다. 이미 열어 둔 상세와 고정 카드는 원래 스냅샷을 유지한다.

과거 기술 카드에서 부품 자료가 없으면 상세에 ‘새 자료로 열기’와 기존 카드 갱신 경로를 제공한다. 새 자료로 여는 동작은 조회 화면만 바꾸며 고정 카드를 수정하지 않는다. 카드 갱신은 기존 전후 확인·중복 방지 흐름을 사용하고 UID·위치·크기·불투명도·표시 항목을 보존한다.

화면 이동과 응답은 요청 번호·스냅샷·종류·정의·언어에 묶는다. 페이지 요청에는 검색어·필터·정렬 기준을 함께 묶고, 바뀐 조건의 과거 응답을 버린다. 언어 변경 후 돌아가면 같은 정의를 새 언어로 다시 읽는다. 탐색 이력은 최대 32개로 제한한다.

## 9 저장과 개발 구조

기존 파서와 원문 캐시를 사용하고 실제 weapon_component_template 추출기를 명시적으로 추가한다. 기존 합성 component_template 계약은 유지한다. 파일 목록과 분석 정책에 TXT·두 CSV·계열·변수 자료를 포함한다. 변수만 있는 파일과 설명 파일도 원본 목록에서 누락하지 않는다.

현재 기술 전용 검색과 기술/이벤트 중심 저장·참조 경로를 무기까지 확장한다. 새 엔티티는 부품 종류와 무기 subtype을 구분한다. 기술 검색 기본 결과에 무기가 섞이지 않게 하고 기존 CLI·AnswerFact·기술/참조/비교 카드 계약을 보존한다.

부품→요구 기술과 부품→상위 부품은 별도 관계로 저장한다. 이벤트 참조로 돌려 쓰지 않는다. 관계 대상의 종류까지 확인하고 같은 ID의 중복 정의는 후보로 남긴다. 한 엔티티의 관계 occurrence는 관계 종류 사이에서도 충돌하지 않게 관리한다. 역방향 기술 목록은 이 관계에서 조회한다.

CSV는 고정된 세미콜론 형식으로 읽고 중복 헤더를 dict로 덮기 전에 식별한다. BOM·줄바꿈·주석·따옴표·빈 셀·end 열을 명시적으로 다루고 알 수 없는 열은 원문과 함께 보존한다. 멀티라인 셀을 다룰 때도 실제 논리 행과 원문 위치를 유지한다.

기존 파일 크기·총량 한도를 유지한다. CSV는 파일당 10만 행·128열·셀당 64KiB, 파일별 파생 산출물은 16MiB로 제한한다. 할당·확장 전에 한도를 청구하고 넘으면 활성화하지 않는다. 화면은 기본 20개/최대 100개씩 조회하며 하나의 상세 표시 데이터는 64KiB로 제한한다. 조건·설명·근거가 긴 경우 섹션별로 나누어 요청하고 생략된 항목과 더 보기를 표시한다. 일부 섹션의 한도로 정상 부품 전체를 빈 화면으로 만들지 않는다. 전체 원문은 기존의 제한된 원문 보기로 읽는다.

파일별 추출 산출물, 무기 검색 투영과 역방향 관계를 같은 정책 버전으로 관리한다. TXT·CSV·변수·계열·번역 변경과 누락 key의 추가·삭제·충돌이 영향을 주는 결과를 갱신한다. CSV 하나가 바뀌었다고 전체 번역을 다시 파싱하거나 상세를 열 때마다 전체 표를 읽지 않는다.

발행은 기존 writer lock과 활성 자료 전환 흐름을 사용한다. 정의·수치·관계·출처가 준비된 뒤 전환하고 실패·취소 시 이전 활성 자료를 유지한다. 조회 스레드와 색인 스레드의 연결을 분리하며 SQL 조건은 스냅샷과 종류에 묶는다. 새 UI 프레임워크·외부 서비스·게임 메모리 접근은 추가하지 않는다.

## 10 개발 순서와 완료 범위

1. 실제 무기·계열·CSV의 원문 위치, 필드별 범위와 우선순위 모델을 연결한다.
2. 부품 저장·증분 산출물·검색·요구 기술/상위 부품 관계를 연결한다.
3. 계열별 목록·무기 검색·읽기 쉬운 상세·항목별 근거를 만든다.
4. 기술과 부품의 왕복 이동·탐색 복원·새 자료 적용 흐름을 연결한다.
5. 기능 작성 100% 이후 아래 필수 항목만 확인한다.

완료 범위는 청색 레이저 기술에서 관련 계열과 크기를 선택해 기본 성능·조건·근거를 읽고, 같은 자료의 요구 기술과 명시된 상위 부품으로 이동할 수 있는 상태다. 이전 카드와 검색·게임 입력 통과 동작을 유지한다. 실행 파일 생성·커밋·푸시·PR·병합·배포는 각 실행 범위를 구분한다.

- 실제 청색 레이저 계열의 크기별 정의, 일반/변이 표의 독립 처리, 요구 기술과 상위 부품의 같은 스냅샷 이동.
