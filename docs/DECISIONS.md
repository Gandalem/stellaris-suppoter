## ADR-015 — Windows 게임 오버레이 방향 (2026-10-12)

F-020의 최종 사용자 경험은 게임 위에 뜨는 별도 Windows 오버레이로 계획합니다. PySide6/Qt는 후보이고 확정이 아닙니다. TASK-022 이후 선택적 TASK-032/E-048에서 전역 핫키 충돌, 접힘 입력 통과, 게임 종료·최소화와 창/DPI 위험을 검증합니다. TASK-029와 TASK-032 후 TASK-030/E-046이 최종 구현을 담당합니다. 게임 주입·그래픽 후킹·메모리 읽기를 배제하며, 실제 Windows 실험에서 실패하면 프레임워크/호환 범위를 다시 결정합니다. SQLite migration 없음. 계획 승인·기능 완료·실게임 호환성은 별개입니다.


## ADR-016 — UI 독립 참조 서비스와 선택적 이벤트 색인 (2026-10-21)

TASK-015/F-010/F-011/E-028/E-029는 기존 stdlib 파서·SQLite v1을 활용한다. 이벤트 색인은 --include-events로 명시하며 정책 identity에 extractor 버전을 포함한다. 기본 기술 snapshot identity와 search/show 범위는 보존한다. 공통 ReferenceService와 snapshot 고정 카드 인터페이스를 선택해 이후 메인 창/오버레이에서 같은 결과를 사용한다. 대안인 GUI 선행 구현과 전체 도메인 저장 확장은 현재 참조 조회에 필요하지 않아 후속으로 둔다. 스키마 migration과 신규 런타임 의존성 없음. 소유자가 2안 구현을 명시적으로 승인했고, 기능 구현 100% 뒤에 검증을 시작하도록 작업 순서를 지정했다. 실제 게임 문법/화면 호환성 근거가 확보되면 지원 경로와 UI 결정을 개정한다.


## ADR-017 — 내용 비교와 파일 산출물 재사용 분리 (2026-10-21)

TASK-016/F-012/F-011/E-030/E-031의 1안은 먼저 의미 비교 기준을 고정하고 증분 처리가 전체 처리와 같은 snapshot을 구성하도록 한다. snapshot 종속 entity key/span을 비교 identity에서 제외하고 전후 근거로 보존한다. 파일 중간 결과는 SHA·정책별 snapshot-neutral JSON을 기존 private cache/settings로 연결한다. 별도 DB schema/외부 캐시 서비스/런타임 라이브러리는 추가하지 않는다. 번역 의존성별 부분 최적화와 영속 diff 테이블은 후속 측정 때 결정한다. 소유자는 기능 100% 뒤 필수 검사만 실행하고 Git 통합은 요청 시 별도로 진행하도록 승인했다. TASK-015는 로컬 구현/평가 완료로 닫고 원격 통합과 구별한다.


## 2026-10-21 — 관리창·카드 오버레이 1안

사용자 승인으로 Qt/PySide6-Essentials를 선택 의존성으로 사용한다. 기존 CLI와 snapshot 서비스는 유지하고 UI의 단일 worker가 DB를 소유한다. 게임은 전체 실행 경로/PID/HWND로 식별하며 작은 개별 카드 창에 passive 입력 통과를 적용한다. Steam 레지스트리/라이브러리 manifest의 읽기 전용 자동 탐색과 수동 경로 우선을 허용한다. 색인은 명시적 버튼 동작이다. 기능 코드 전체 작성 후 필수 검사만 진행하며 Git 통합/원격 CI/배포는 별도 요청이다. TASK-033에서 이전 TASK-020 선행 main 통합 문구보다 사용자 승인된 로컬 개발 순서가 우선한다.


## 2026-10-25 — 로컬 데이터 저장 2안

사용자가 전체 기능 작성 후 필수 검수 조건으로 개발을 승인했다. 기존 스냅샷 DB 스키마는 유지하고, 전체 번역은 별도 localisation-products.sqlite3의 불변 파일 버전에 순차/배치 저장한다. 기존 API용 스냅샷에는 기술 이름/설명 및 참조에 필요한 항목을 투영한다. 전체 번역 비교는 파일 카탈로그를 스트리밍한다. 저장된 검색 투영은 canonical 행 fingerprint와 파일 digest로 묶어 재시작 후 재사용한다. 색인/검색은 별도 Qt worker가 DB 연결을 소유한다. 파서의 현행 게임 lexical 확장은 새 파일 카탈로그 버전에만 적용하고 기존 스냅샷 reader 동작을 유지한다. 활성화는 기존 원본 재확인/CAS/부분 사용 선택을 따른다. 실패한 v2 임시 스냅샷만 writer lock 안에서 재구축하며 이전 카드·스냅샷을 삭제하지 않는다. 누락 키 및 언어 대체도 파생 캐시 의존관계에 포함한다.


## ADR-021: 기술 카드 정적 정보 (2026-10-25)

사용자가 승인한 [2안](TECH-CARD-INFO-OPTION-2.md)을 적용한다. 기존 AnswerFact와 CLI 원문 계약을 보존하고 GUI의 `card_view`에 같은 스냅샷의 표시값·상태·출처를 추가한다. `common/scripted_variables`와 기술 파일 최상위 선언을 내용별 파일 산출물로 저장하고 정책 `card_values=static-card-values-1`을 스냅샷 정체성에 포함한다. 단일 숫자·한 단계 변수만 연결하며 중복·범위 충돌·불완전 범위는 확정하지 않는다. 과거 자료는 현재 파일로 보충하지 않는다.

기술 요약은 일반 텍스트와 Qt 글자 배치로 그리며 카드 내부 스크롤을 제거한다. 상세·항목 선택·관리·전후 갱신 확인은 기존 Qt 관리창에서 수행한다. UID/스냅샷/정의/언어와 요청 토큰을 모두 확인하고 중복 갱신을 차단한다. 새 데이터로 자동 전환하거나 사용자 카드를 자동 삭제하지 않는다. 엔진 계산·세이브·모드 적용·연구 시간/등장 확률은 별도 범위다.


## ADR-022 무기 부품과 기술 연결 2026-10-25

사용자가 [2안](WEAPON-COMPONENT-OPTION-2.md)의 개발을 승인했다. 실제 weapon_component_template/계열/CSV는 순서·원문 위치를 보존하는 파일 산출물로 저장한다. SQLite v1의 component_template 엔티티와 요구 기술/상위 부품 전용 관계를 사용하고 이벤트로 위장하지 않는다. 스냅샷 정책 weapons=weapon-data-2와 불변 파일 manifest를 적용한다. 일반 표와 변이 표의 우선순위를 혼동하지 않고 변이 표는 결합 정책 밖의 선언값으로 남긴다. 기술 전용 기본 검색과 기존 카드 원문 계약은 유지한다.

관리창의 통합 무기·기술 상세와 최대 32개 탐색 이력을 사용한다. 선택한 항목의 근거는 별도 제한된 요청으로 읽는다. 새 색인 시 조회 자료를 선택하되 과거 상세/카드를 자동 갱신하지 않는다. 기존 Qt/작업 스레드/원문 캐시를 활용한다. 기능 전체 작성 후 필수 검수만 수행하며 Git 통합·배포는 별도다.

ADR-022 후속 사용자 요청(2026-10-25): 무기 상세에서 항목별 값 근거 전용 UI를 제거한다. 출처 확인의 내부 동작/저장/API는 유지하며 수치·자원·조건·특수 작용과 관계 탐색을 보존한다. 쿨다운·발사 준비 시간처럼 이전 항목 목록에만 있던 수치는 기본 상세로 이동한다. 기술 상세의 기존 탭은 이번 변경 대상이 아니다.


## ADR-023 무기 요약 카드와 기술 연결 2026-10-25

사용자가 [무기 카드 2안](WEAPON-CARD-OPTION-2.md) 개발을 승인했다. 기존 무기 상세를 카드 조회에도 사용하고 수치/자원/상태를 표시용으로만 투영한다. kind=weapon/domain=component_template과 확정 entity_key로 개별 크기를 고정한다. 같은 스냅샷의 기술/명시 상위 부품을 사용자 선택으로 추가 고정한다. 기존 근거 패널 제거 결정을 유지한다.

카드 창은 UID별로 유지하고 추가/제거/갱신한 대상만 조회한다. 설정 저장은 경로별 짧은 잠금과 파일 digest 비교 후 기존 임시 파일 교체로 처리하며 첫 무기 카드 전 기존 설정을 백업한다. 새 설정이 저장된 뒤 창과 목록을 반영한다. 갱신 전후 확인은 선택한 정의와 현재 카드/언어/설정 세대에 고정하고 적용 직전에 재조회·중복을 다시 확인한다. 기존 기술/참조/변경 카드와 전체 24장 한도를 보존한다. 전체 기능 작성 이후 필수 검사만 진행하고 Git 통합/배포는 별도다.


## ADR-024 무기 비용 제어와 미확정 안내 2026-10-25

사용자 요청으로 비용의 mult/multiplier 및 조건·인라인 제어 필드를 자원 행에서 분리한다. 조건·배율·펼치지 않은 인라인 구문이 있는 범위의 금액은 고정 비용으로 확정하지 않는다. cost/upkeep별 resource_scopes 코드와 기존 원문/출처를 보존하고 중복 블록의 선언은 후보로 남긴다. 같은 원인의 변이 표 policy_required는 상세·카드·접근성·갱신 미리보기에서 한 번만 요약하며 원래 개별 필드 상태는 유지한다. 변이 표 엔진 적용 규칙이나 동적 비용 계산을 새로 확정하지 않는다. 파일 중립 산출물과 스냅샷 형식은 그대로 사용하므로 추가 색인이 필요 없다.
