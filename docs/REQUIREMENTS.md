# 기능·비기능 요구사항

각 F-ID의 상태는 [기능 원장](../harness/features.json)에만 기록합니다. 수용 조건은 설계 요구이며 현재 달성 사실이 아닙니다. 세부 입력·출력은 [데이터 계약](DATA_CONTRACTS.md), 검증은 [평가 기준](EVALUATION.md)을 따릅니다.

## v0.1 필수 기능

| ID | 기능 | 수용 조건 |
|---|---|---|
| F-001 | 재현 가능한 개발 환경 | Python 3.11+ 깨끗한 가상환경에서 설치·help·테스트가 동작하고 의존성 범위가 기록된다. |
| F-002 | 설정·진단 | 명시 경로를 검증하고 미존재·접근 불가·쓰기 경로 충돌을 설명한다. 버전·FTS 가용성과 네트워크 비활성을 보고한다. |
| F-003 | 안전한 파일 목록·버전 | 허용 루트 내 상대 경로·크기·SHA-256을 기록한다. 버전 불명은 unknown; DLC 설치·소유·활성을 구별한다. |
| F-004 | 보존형 정적 파서 | 순서·중복 키·중첩·문자열·주석 위치를 보존하고 오류 행을 보고한다. 알 수 없는 구조를 손실 없이 표시한다. |
| F-005 | 도메인 엔티티 | 기술 수직 슬라이스 후 명시한 범주별 ID·표현식·조건·출처를 추출한다. 동명이 ID는 덮어쓰지 않는다. |
| F-006 | 현지화 | 한국어·영어·ID 대체가 결정적이고 참조 순환·누락을 표시한다. 동적 표현식은 실행하지 않는다. |
| F-007 | 로컬 스냅샷 DB | 동일 입력·동일 도구 정책의 식별자가 안정적이고 중단된 색인이 활성 DB를 손상시키지 않는다. |
| F-008 | 한국어·영문·ID 검색 | 정규화·별칭·짧은 문자열 fallback·범주 필터를 지원한다. 사용자 문자열이 SQL/FTS 명령으로 실행되지 않는다. |
| F-009 | 근거 기반 정적 답변 | 모든 반환 엔티티와 사실 필드에 추적 가능한 출처가 있다. 없으면 not_found/partial/unsupported로 설명한다. |
| F-010 | 제한된 참조 그래프 | 정적으로 확인한 기술 선행·이벤트 참조를 타입별 edge로 보존하고 미해결·순환·깊이 제한을 표시한다. |
| F-011 | CLI 사용 흐름 | init/doctor/index/search/show/refs/snapshots/diff가 문서 계약에 맞고 JSON stdout과 로그 stderr가 분리된다. |
| F-012 | 변경 감지·재색인 | 추가·변경·삭제를 구별하고 새 스냅샷으로 전환한다. 재검사하지 않은 캐시는 최신으로 표시하지 않는다. |
| F-013 | 안전·개인정보 | 게임 원본 쓰기, 루트 탈출, 무단 통신, 공개 로그의 키·개인 경로 노출을 부정 테스트로 차단한다. |
| F-014 | 품질·배포 게이트 | 오프라인 합성 회귀, 설치/CLI 스모크, 성능 측정, 로컬 검증 기록과 릴리스 문서가 준비된다. |

| F-016 | 선택적 LLM/RAG | 검색 근거만 주입, 출처 검증, 예산·타임아웃·동의, 모델 미설정 시 정적 출력으로 복귀. |
| F-017 | 모드 적용 분석 | 실제 로드 순서·replace_path·파일 및 객체 충돌 규칙을 범주별 검증한 뒤 effective 상태를 표시한다. |
| F-018 | 세이브 읽기 | 허용된 로컬 입력만 읽고 버전·형식·크기·압축 안전성을 확인한다. 필드 의미 미확인은 계산에 쓰지 않는다. |

| F-020 | 로컬 UI | CLI 서비스 계층을 재사용하고 기본 loopback 바인딩, 경로 보호, 안전한 텍스트 렌더링을 검증한다. |

## 비기능 기준

N-01 정확성: 검증된 원문 인용 위치 일치율 100%, 평가에 포함된 다른 스냅샷 누출 0건, 미지원 의미 해석의 조용한 확정 0건.

N-02 결정성: 동일 corpus·정책·스키마의 엔티티와 검색 tie-break가 안정적이다. 시간·절대 경로는 콘텐츠 식별자에 섞지 않는다.

N-03 격리: 기본 네트워크 off, 원본 read-only, 저장소 밖 개인 캐시. 부작용이 있는 기능은 명시 옵션과 확인이 필요하다.

N-04 견고성: 오류 파일·큰 입력·권한 실패·디스크 부족·중간 취소·동시 writer 상황에 진단과 복구 경로가 있다. 안전 실패와 데이터 부분 성공을 구별한다.

N-05 자원: 기본 제안 한도는 파일당 16 MiB, 총 512 MiB, 깊이 128, 파일 수 50,000, 방문 항목 수 100,000, 질의 512문자, 결과 100개다. 이는 게임의 실제 규모가 아닌 보수적 제품 정책이며 설정·평가와 함께 조정한다. 한도 초과를 조용히 생략하지 않는다.

N-06 성능: 10,000개 합성 엔티티에서 warm 검색 p95 500 ms 이내를 초기 목표로 측정한다. 환경·원시 측정값을 기록하며 측정 전 성능을 보장하지 않는다. 절대 시간은 CI 필수 통과 기준보다 먼저 기준선을 마련한다.

N-07 호환성: Windows를 첫 사용자 검증 목표로 하되 사용자의 OS는 아직 미확인이다. Linux는 자동 테스트 대상, macOS는 실제 스모크 전 best-effort다. 게임 전체를 모든 플랫폼에서 검증했다고 주장하지 않는다.

## 변경 관리

범위나 수용 조건을 바꾸면 F-ID, 연관 TASK-ID, E-ID, 데이터 계약, 결정 기록을 같은 PR에서 바꿉니다. 실패한 평가를 제거하거나 threshold를 낮출 때 사유·기존 결과·새 기준을 기록하고 검토받습니다.
