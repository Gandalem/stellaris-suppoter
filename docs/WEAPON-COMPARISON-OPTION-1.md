# 같은 크기 무기 비교 1안 초안

함선 설계 중 같은 슬롯 크기의 무기 두 개를 선택해 기본 수치를 나란히 읽고, 필요한 무기를 기존 오버레이 카드로 고정한다. 수치 차이를 보여주고 무기 선택은 플레이어가 판단한다. 기존 무기 조회·고정 카드·기술 연결을 활용한다.

## 1 기본 사용 흐름

1. 무기 상세의 무기 비교를 누르거나 편집 중인 무기 카드에서 비교를 연다.
2. 선택한 무기를 기준 무기 A로 둔다.
3. 같은 자료·같은 슬롯 크기의 후보에서 비교 무기 B를 고른다.
4. 항목별 A 값·B 값·차이를 확인한다.
5. A 카드 고정 또는 B 카드 고정을 눌러 원하는 무기를 게임 위에 남긴다.
6. 요구 기술·상위 부품이 궁금하면 같은 자료의 기존 상세를 열고 뒤로 돌아온다.

비교는 관리창의 기존 무기 검색 안에 별도 화면으로 연다. 큰 팝업을 계속 쌓거나 새 사이드바 메뉴를 늘리지 않는다. 비교 화면 진입 자체는 고정 카드나 홈의 자료 선택을 변경하지 않는다.

## 2 비교 대상 선택

상단에 기준 무기 A와 비교 무기 B를 구분한다. 각 칸에는 이름·슬롯 크기·명시된 계열과 대상 변경 동작을 둔다. A/B 바꾸기로 좌우를 교환하고 차이 방향도 함께 바꾼다.

B 후보는 A의 스냅샷과 실제 size 값을 사용해 좁힌다. 소형·중형·대형 같은 표시 이름이나 부품 ID 접미사로 크기를 추정하지 않는다. 슬롯 크기가 없거나 불명확한 무기는 같은 크기로 확정하지 않는다. 계열 묶음은 펼쳐 개별 크기와 정의를 고른다. 같은 ID의 중복 정의도 개별 후보로 유지한다.

A와 같은 개별 정의를 B에 넣으면 같은 무기임을 알리고 다른 대상을 고르게 한다. 같은 크기라도 에너지·실탄 등 다른 계열은 비교할 수 있다. 슬롯 제한·추가 조건·현재 함선 장착 가능 여부가 같다고 판단하지 않는다.

처음에는 일반 무기 수치 표와 직접 해석 가능한 TXT 기본값을 중심으로 비교한다. 선택한 대상에 미확정 항목이 있으면 해당 항목의 차이를 계산하지 않는다. 변이 수치나 조건 비용을 지원하기 위해 게임 상태를 추정하는 기능은 추가하지 않는다.

A를 바꿨을 때 기존 B가 같은 자료·크기의 다른 정의라면 유지한다. 자료나 크기가 달라지거나 A와 같은 정의가 되면 B를 비우고 다시 선택한다. B가 확정되기 전에는 이전 비교값을 새 대상의 값처럼 남기지 않는다.

## 3 비교 화면 구성

| 영역 | 내용 |
|---|---|
| 상단 | A/B 이름·크기·계열, 대상 변경, 좌우 바꾸기 |
| 기본 정보 | 무기별 추가 조건·특수 작용 표시 |
| 비교 표 | 항목, A 값, B 값, 차이 B−A |
| 선택 항목 | 피해 특성·관통·유지비 펼치기 |
| 하단 동작 | A/B 상세 열기, A/B 카드 고정, 뒤로 |
| 자료 기준 | 같은 스냅샷의 기본 수치, 필요한 일부 자료·이전 자료 표시 |

기본 표는 피해 범위·최소/최대 사거리·명중률·추적률·전력·자원별 제작 비용을 표시한다. 선체/장갑/보호막 피해 배율과 관통률, 자원별 유지비는 추가 항목으로 펼친다. 선택 항목을 바꿔도 A/B 선택은 유지한다.

변경된 행은 색과 차이 숫자로 구분한다. 색만으로 정보를 전달하지 않고, 증가를 초록색 승리나 감소를 빨간색 패배로 판정하지 않는다. 긴 숫자는 중간에서 잘라 다른 값처럼 보이지 않게 한다. 작은 창에서는 열 너비 조정과 표 스크롤을 사용한다.

## 4 수치 차이 표시 규칙

| 항목 | 차이 표시 |
|---|---|
| 기본 피해 | 최소 피해와 최대 피해를 각각 비교 |
| 최소/최대 사거리 | 각각의 직접 정의된 거리끼리 비교 |
| 명중률·추적률·관통률 | 퍼센트포인트 차이로 표시 |
| 피해 배율 | 배율 값의 차이를 표시 |
| 전력 | 소비/공급 종류를 보존해 같은 종류끼리 비교 |
| 제작 비용·유지비 | 같은 자원 ID끼리 비교 |

차이의 기준은 B−A다. 양수는 증가, 음수는 감소, 0은 동일로 표시한다. 첫 범위에서는 상대 증가율을 추가하지 않는다.

예를 들어 피해가 A 8–21, B 13–35이면 최소 +5·최대 +14로 보여준다. 두 피해 범위가 겹쳐도 승자를 정하지 않는다. 명중률 A 90%, B 95%의 차이는 +5%p다. 피해 배율 ×1.25와 ×1.50의 차이는 배율 +0.25로 표시한다. 이 예시는 표시 규칙 설명용이며 특정 무기의 실제 데이터로 고정하지 않는다.

최소 사거리 정의가 없으면 선언 없음으로 표시하고 0으로 바꾸지 않는다. 사거리가 길거나 최소 사거리가 짧다는 이유로 모든 상황에서 유리하다고 판단하지 않는다. 발사 간격·준비 시간의 원문 단위는 기존 상세에서 확인하며 이번 비교에 초 단위로 환산해 넣지 않는다.

전력은 셀마다 소비/공급을 함께 표시한다. 둘 다 소비면 소비량의 차이, 둘 다 공급이면 공급량의 차이를 표시한다. 소비와 공급이 바뀌거나 0과 전력 유형이 전환되면 유형 변경으로 알리고, 서로 다른 절댓값을 빼서 함선 잔여 전력의 변화처럼 표시하지 않는다. 부호 규칙이 확정되지 않으면 차이를 계산하지 않는다.

평균 피해·DPS·상대 회피 반영 명중·제국/함선 보정·승률은 계산하지 않는다.

## 5 자원별 비용 비교

A와 B에 직접 선언된 자원의 합집합을 만들고 정확한 자원 ID로 행을 연결한다. 표시 이름이 같아도 ID가 다르면 별개 자원이다. 합금·에너지·희귀 자원을 단일 비용 숫자로 합치지 않는다. 제작 비용과 유지비도 구분한다.

양쪽 모두 같은 자원의 단일 고정값이 확인된 경우에만 차이를 계산한다. 한쪽에 자원 선언이 없으면 선언 없음으로 표시하고 0으로 채워 차이를 만들지 않는다. 실제 숫자 0이 확인된 값은 정상 비교한다.

배율·조건·인라인 스크립트·중복·잘린 범위가 있는 비용은 기존 resource_scopes와 개별 상태를 사용한다. 확인되지 않은 총비용을 계산하지 않는다. 한쪽의 비용을 확정할 수 없어도 상대의 정상 비용과 다른 성능 수치는 그대로 읽을 수 있게 한다.

중복 cost/upkeep 블록은 더하거나 마지막 값으로 선택하지 않는다. mult/multiplier·조건문은 자원 행에 넣지 않는다. 전체 자원 범위를 읽지 못해 같은 자원의 추가 선언을 배제할 수 없는 경우에도 차이를 계산하지 않는다.

## 6 미확정 값과 조건 안내

정의 없음·자료 없음·중복·동적 계산·변이 적용 규칙을 구분한다. 각 셀에는 짧은 상태를 표시하고 차이 칸에는 숫자 대신 비교 불가 표시를 사용한다. 같은 원인의 자세한 안내는 무기별 한 곳에 요약한다. 현재 카드에서 줄인 변이 안내를 표의 모든 행에 다시 반복하지 않는다.

두 값이 모두 없거나 미확정이라고 해서 동일하다고 표시하지 않는다. 확정된 0끼리 비교한 결과와 구분한다. 필드 하나를 비교할 수 없어도 정상 행 전체를 비우지 않는다. 출처 손상이나 정의 불일치는 일반 미확정과 구분해 결과 표시를 중단하고 다시 읽기 경로를 제공한다.

같은 크기라는 이유만으로 장착 대상·특수 작용·설계 조건이 같다고 표시하지 않는다. 각 무기의 조건/특수 작용 표시에서 같은 자료의 상세로 이동할 수 있게 한다. 연구 보유 상태와 현재 함선의 호환 여부는 판정하지 않는다.

## 7 자료 기준과 과거 카드

비교 한 건은 하나의 스냅샷에 고정한다. 관리창에서 시작하면 선택한 조회 자료를, 고정 카드에서 시작하면 해당 카드의 자료를 사용한다. 다른 자료에 있는 두 카드를 그대로 섞어 비교하지 않는다.

사용자가 다른 자료의 무기를 고르려 하면 현재 비교 자료에서 다시 고르도록 안내한다. 과거 자료에 원하는 무기가 없다고 현재 설치 파일에서 값을 보충하지 않는다. 동일 무기의 패치 전후 비교와 서로 다른 무기의 성능 비교도 별도 동작으로 유지한다.

새 색인이 완료돼도 열린 비교는 기존 자료를 유지한다. 새 자료로 비교를 선택하면 새 자료에서 A/B를 다시 고르는 흐름을 열고, 이전 비교는 뒤로 가기 이력에 남긴다. 이 동작은 과거 고정 카드를 갱신하지 않는다.

검색·계열 펼침·A/B 선택·추가 항목·스크롤·좌우 방향을 기존 최대 32개 이력 안에서 복원한다. 언어가 바뀌면 같은 정의를 새 언어로 다시 읽고 이전 언어의 응답을 새 화면에 반영하지 않는다. 비교 선택은 실행 중 상태로 유지하고 종료 후에는 초기화한다. 기존 고정 카드는 현재 방식대로 복원한다.

## 8 상세와 카드 연결

A 상세 열기와 B 상세 열기는 같은 스냅샷·개별 정의의 통합 상세를 사용한다. 그곳의 요구 기술·명시된 상위 부품 이동과 카드 고정은 기존 기능을 재사용한다. 뒤로 돌아오면 비교 대상과 표 위치를 복원한다.

A 카드 고정과 B 카드 고정은 기존 무기 카드 고정을 호출한다. 이미 같은 카드가 있으면 기존 카드를 선택하고 표시 항목·좌표·크기를 바꾸지 않는다. 다른 카드와 공유하는 24장 한도를 유지한다. 비교 화면을 열었다는 이유로 두 카드를 자동 고정하지 않는다.

이번 단계는 개별 무기 두 장을 고정하는 방식이다. 비교 표 자체를 하나의 새 오버레이 카드로 저장하거나 카드 설정 형식을 다시 확장하지 않는다.

## 9 데이터와 코드 연결

기존 WeaponService의 원본 검증·개별 정의·수치/자원 상태를 사용한다. 화면에 표시한 쉼표·%·×·한국어 문자열을 다시 파싱해 계산하지 않는다. 조회 단계에서 확인된 유한 십진 숫자와 단위로 비교용 값을 구성한다.

피해는 최소/최대의 확인된 숫자를 따로 보존한다. 명중·추적·관통의 기본 비율은 기존 단위 규칙으로 변환하고 차이는 퍼센트포인트로 계산한다. 기존 상세의 해석 상태가 확정된 값에만 계산을 허용한다. 숫자 원문 최대 64자와 십진 정밀도 규칙을 이어받고, 덧셈/뺄셈/백분율 변환에서 기본 정밀도에 의해 유효 숫자가 잘리지 않게 한다.

기존 comparison.py는 패치/스냅샷 비교에 사용하므로 두 무기 비교의 의미를 섞지 않는다. 별도 무기 비교 표시 모듈과 worker 요청을 추가하고 관리창의 무기 검색 안에 화면을 연결한다. 같은 자료의 양쪽 정의와 크기를 확인한 후 하나의 비교 응답으로 반영한다.

요청은 스냅샷·A/B ID/정의·좌우 순서·언어·선택 항목·설정 세대·요청 번호에 묶는다. 대상 선택이나 설정이 바뀌면 이전 응답을 버린다. 새 대상이 로딩 중이면 이전 차이 표를 지우고 현재 선택을 표시한다. 서로 다른 시점의 A/B 응답을 임의 결합하지 않는다.

조회는 기존 작업 스레드에서 처리한다. 비교 진입·대상/언어/항목 변경 시 필요한 정보를 읽고 화면 그리기나 게임 창 추적 타이머에서 전체 데이터를 다시 읽지 않는다. 후보 목록과 많은 자원 행은 기존 기본 20개/최대 100개 단위의 조회 한도를 사용하고 추가 범위를 알린다. 비교 결과는 핵심 표와 식별 정보를 64KiB 안으로 제한하며 긴 목록은 페이지로 읽는다. 원문은 기존 상세에서 연다.

새 UI 프레임워크·서버·실시간 게임 수집은 추가하지 않는다. 저장 자료와 카드 설정은 재사용하고 비교를 위한 추가 색인을 기본 동작으로 요구하지 않는다.

## 10 개발 순서와 필수 완료 확인

개발 순서는 비교 대상/단위/정적값 모델 → 같은 자료·같은 크기 후보 선택 → 비교 표와 상태 안내 → 상세/카드 연결 → 이력·응답 일관성이다. 기능 작성 진행률 100% 이후 다음 필수 항목만 확인한다.

- 같은 크기 일반 무기 두 개의 기본 수치와 자원별 차이, 피해 최소/최대·퍼센트포인트·전력 유형 표시.
- 자료/크기 불일치·같은 대상·중복 정의·한쪽 선언 없음/0·조건 비용·변이 미확정과 수치 과장 방지.
- A/B 바꾸기와 대상 변경·로딩·뒤로 가기·언어 변경에서 이전 응답과 차이 값이 섞이지 않는지 확인.
- 긴 이름/숫자·작은 창·다수 자원 표시, 같은 원인 안내가 반복되지 않는 구성.
- A/B 상세·요구 기술·상위 부품 이동과 개별 고정, 기존 카드/좌표/한도 보존.
- 최종 실행 파일에서 실제 일반 무기 한 쌍을 선택해 비교하고 카드를 고정하는 최소 흐름.

완료 기준은 같은 자료의 소형 청색 레이저와 소형 자외선 레이저를 선택해 기본 수치·자원별 차이를 읽고, 원하는 무기를 고정한 뒤 상세와 비교 화면을 왕복해도 대상과 기존 카드가 유지되는 상태다. 커밋·푸시·PR·병합·배포는 별도 실행 범위로 둔다.
