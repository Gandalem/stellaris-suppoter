# 무기 카드 고정과 기술 카드 연결 2안 초안

함선 설계 중 필요한 개별 무기의 기본 수치를 게임 위에 남기고, 요구 기술과 명시된 상위 부품을 찾아 원하는 카드만 추가한다. 카드의 읽기·편집·고정 해제를 분명히 나누고 기존 기술 카드와 함께 사용할 수 있게 만든다. [1안](WEAPON-CARD-OPTION-1.md)은 보존한다.

## 1 재검토에서 바꾼 결정

| 1안에서 보완할 점 | 2안의 결정 |
|---|---|
| 수치를 위에서부터 나열하면 작은 카드에서 뒤쪽 항목이 사라짐 | 기본 여섯 항목의 우선순위와 숫자를 보존하는 줄바꿈·접기 규칙을 정함 |
| 피해·명중률만 보면 같은 수치가 같은 역할의 무기로 보임 | 무기 이름·크기·명시된 계열과 추가 조건/특수 작용 표시를 분리 |
| 연결마다 상세 화면을 반복해서 열어야 함 | 같은 자료의 연결 목록에서 대상 선택 후 바로 고정하는 동작 추가 |
| 이미 고정된 카드가 어디 있는지 알기 어려움 | 고정됨 표시와 기존 카드 선택, 편집 상태에서만 짧은 테두리 강조 |
| 숨김과 고정 해제의 차이가 불분명함 | 전체 숨김은 고정 목록 유지, 한 장 고정 해제는 선택 카드만 제거 |
| 추가할 때 계단식 위치와 전체 창 재생성으로 배치가 흔들릴 수 있음 | 보이는 빈 영역에 새 카드만 추가하고 기존 창과 배치는 유지 |
| 갱신 확인창을 띄운 사이 대상 자료가 바뀔 수 있음 | 확인한 전후 정의·언어·설정 세대까지 묶어서 적용 |
| 새 카드 종류가 기존 참조/변경 카드 분기로 넘어갈 수 있음 | 종류별 설정·조회·표시·상세·갱신·제거 경로를 명시적으로 구분 |
| 모니터 이동과 배율 변경 시 좌표가 두 번 확대될 수 있음 | Qt 논리 좌표와 Windows 네이티브 좌표의 변환 경계를 고정 |
| 카드 수가 늘수록 재조회와 설정 저장이 반복될 수 있음 | 정적 자료는 변경 시 읽고 저장 확정 후 필요한 카드만 반영 |

이 결정들은 현재 코드와 아래 공식 문서를 참고한 프로젝트 설계 선택이다. 다른 앱의 동작이나 플랫폼 API를 우리 앱의 완료 결과로 대신하지 않는다.

## 2 플레이 중 기본 흐름

1. 기술 상세의 관련 무기 또는 관리창 무기 검색에서 계열을 펼친다.
2. 사용할 크기의 개별 무기를 고르고 카드 고정을 누른다.
3. 게임으로 돌아가 기본 성능과 제작 비용을 참고한다.
4. Ctrl+Shift+Space로 편집 모드를 열고 연결 보기를 누른다.
5. 같은 저장 자료에서 요구 기술 또는 명시된 상위 부품을 선택해 고정한다. 자세히 읽고 싶으면 상세 열기를 선택한다.
6. 카드 보기로 돌아가 필요한 정보만 남긴 채 플레이한다.

계열 묶음은 검색 목록의 표시 방식이다. 카드에는 개별 부품·크기·정의를 저장한다. 다른 크기나 다음 단계 무기는 사용자가 직접 선택하며 원래 카드는 그대로 유지한다. 게임 위 기술 검색창은 기존 동작을 유지하고 새 무기 검색의 시작점은 관리창으로 둔다.

## 3 무기 카드의 읽기 구성

| 영역 | 표시 규칙 |
|---|---|
| 제목 | 무기 이름, 크기 배지, 확인된 계열이 있으면 계열명 |
| 피해 | 기본 피해의 최소–최대 범위 |
| 사거리 | 최대 사거리와 직접 정의된 최소 사거리 |
| 명중과 추적 | 기본 명중률·추적률을 같은 줄에 배치하되 항목별 선택은 유지 |
| 전력 | 소비/공급을 구분하고 0은 전력 변화 없음으로 표시 |
| 제작 비용 | 자원 이름과 비용을 자원별로 표시 |
| 추가 특성 | 직접 선언된 추가 조건·특수 작용이 있으면 짧은 표시 |
| 하단 기준 | 기본 게임 파일 기준과 필요한 일부 자료/이전 자료 표시 |

소형 청색 레이저는 기본 피해 8–21, 최대 사거리 40, 명중률 90%, 추적률 50%, 소비 전력 7, 합금 비용 15를 참고 예로 사용한다. 카드에는 선택한 자료의 실제 표시값을 사용한다. 이것은 연구 완료나 제국 보정이 반영된 성능 표시가 아니다.

기본 항목은 피해·사거리·명중·추적·전력·제작 비용이다. 선택 항목은 선체/장갑/보호막 피해 배율, 관통률, 자원별 유지비, 요구 기술 이름이다. 추가 조건·특수 작용의 존재는 항목 선택과 별개로 한 곳에 표시해 기본 수치만으로 오해하지 않게 한다. 충족 여부나 효과가 더해진 결과를 계산하지 않는다.

0·정의 없음·자료 없음·중복·미지원 식을 구분한다. 최소 사거리 정의가 없으면 최대 사거리만 보여주고 하한을 0으로 만들지 않는다. 비용 정의가 없으면 무료로 표시하지 않는다. 여러 비용을 서로 다른 자원끼리 합산하지 않는다. 발사 간격/준비 시간의 원문 단위는 기존 상세에서 확인한다.

숫자는 기존 십진 표시를 그대로 사용한다. 피해 범위의 한쪽만 잘라 표시하거나 긴 숫자를 생략 부호로 줄여 다른 값처럼 읽히게 하지 않는다. 줄에 안 들어가면 항목을 다음 줄로 보내고, 그래도 들어가지 않으면 그 항목 전체를 추가 항목 수에 포함한다.

제목은 최대 두 줄로 배치한다. 슬롯 크기는 이름이 길어져도 식별할 수 있게 별도 배지로 둔다. 한국어·영어 대체 이름·긴 ID는 Qt의 문자 배치를 사용해 표시하며 게임 텍스트를 HTML로 해석하지 않는다. 부품 ID·원문 경로·스냅샷 식별자는 관리창 상세의 접힌 진단에서 확인한다. 제거한 값 근거 패널은 다시 넣지 않는다.

## 4 작은 카드와 화면 가독성

새 무기 카드는 96 DPI 기준 360×300을 초기 크기로 사용하되 화면 영역·현재 글꼴·편집 버튼이 들어가는 최소 크기를 함께 적용한다. 기존 카드 크기는 보존한다. 보기와 편집 모드를 전환할 때 본문을 위한 공간을 다시 계산한다.

본문 내부 스크롤은 사용하지 않는다. 먼저 선택 항목을 접고, 다수 자원과 요구 기술을 일부 이름 + 외 N개로 줄인 뒤, 기본 항목은 피해 → 사거리 → 명중/추적 → 전력 → 제작 비용 순서로 표시한다. 카드가 작아 보이지 않는 선택 항목은 추가 N항목으로 한 번 알리고 설정에는 남긴다. 합쳐 표시한 명중/추적도 실제 선택 항목 기준으로 세어 중복 집계하지 않는다. 높이를 다시 늘리면 자동 복원한다. 남은 전체 개수가 확인된 경우에만 외 N개를 사용하고, 부분 목록이라 개수를 확정할 수 없으면 추가 항목 있음으로 표시한다.

기본 여섯 항목의 값과 제작 비용은 기본 크기에서 읽히도록 배치한다. 여러 자원은 목록 순서를 유지해 나열하고 추가 수를 표시한다. 모든 수치 항목을 끄면 이름·크기·특성·자료 기준을 유지한다. 빈 공간을 채우려고 설명이나 진단을 자동 삽입하지 않는다.

배경을 채운 카드와 대비되는 글자를 사용한다. 일부 자료·추가 조건·전력 소비/공급은 색만으로 구분하지 않고 텍스트를 함께 표시한다. 투명도는 기존 공통 설정을 유지하며 기본 표시에서 읽을 수 있는 대비를 우선한다. 값의 기준이나 생략된 항목 안내를 마우스 호버에만 숨기지 않는다. Microsoft의 [읽기 대비 지침](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/accessible-text-requirements)과 [보조 설명 사용 지침](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/tooltips)을 참고한 구성이다.

관리창·항목 선택·연결 목록은 키보드로 선택하고 실행할 수 있게 한다. 직접 그리는 카드 요약에도 읽을 수 있는 이름과 전체 요약 텍스트를 연결한다. 보기 상태에서는 접근성을 이유로 게임 입력 통과를 해제하지 않는다.

## 5 보기와 편집과 고정 해제

| 상태 또는 동작 | 결과 |
|---|---|
| 카드 보기 | 수치를 표시하고 클릭·휠·드래그·키 입력은 게임으로 통과 |
| 카드 편집 | 제목 이동·크기 조절과 상세 보기·연결 보기·카드 관리·고정 해제 사용 |
| 전체 숨김 | 창을 숨기고 고정 목록·배치는 유지 |
| 한 장 고정 해제 | 그 카드의 고정 정보만 제거하고 다른 카드·저장 자료는 유지 |

편집 버튼은 게임을 플레이하는 보기 상태에서 보이지 않으며 초점도 받지 않는다. 단순 위젯의 마우스 무시 속성만으로 입력 통과를 판단하지 않고 기존 최상위 창의 입력 통과·초점 비활성 처리를 적용한다. Qt는 [창 전체 입력 통과와 초점 속성](https://doc.qt.io/qt-6/qt.html#WindowType-enum)을 별도로 제공한다.

고정 해제는 편집 중 선택 카드에서 바로 실행할 수 있게 한다. 다른 카드를 연쇄 제거하지 않고 카드를 숨기는 단축키와도 연결하지 않는다. 전체 숨김을 카드 삭제로 표시하는 X 버튼은 사용하지 않는다. 버튼 폭이 좁으면 카드 관리 메뉴에서 같은 이름의 동작을 제공한다. 반복 확인창 대신 명확한 동작 이름과 저장 결과를 사용한다.

HunterPie의 [오버레이](https://docs.hunterpie.com/posts/overlay/)는 디자인 모드에서 위젯 조작과 개별 닫기를 제공하고, [위젯 설정](https://docs.hunterpie.com/posts/widgets/)은 표시와 초기화를 구분한다. 이 앱은 기존 보기/편집/전체 숨김을 유지하고 개별 고정 해제의 의미를 명확히 하는 데 이 원칙을 적용한다. 별도의 위젯 초기화 설정은 추가하지 않는다.

## 6 연결 목록과 원하는 카드 추가

무기 카드의 연결 보기는 관리창의 기존 통합 상세 안에서 같은 자료의 요구 기술·명시된 상위 부품 목록을 연다. 일반 상세 진입은 기존 뒤로 가기 이력을 사용하며, 연결 진입에는 이미 받은 같은 정의의 자료를 재사용하고 해당 목록에 초점을 둔다. 추가 팝업 창을 쌓지 않는다.

목록에서 한 대상을 선택한 뒤 상세 열기 또는 카드 고정을 실행한다. 기술 대상은 기술 카드, 지원 무기 대상은 무기 카드로 고정한다. 여러 대상을 묶어 자동 고정하지 않는다. 기술 상세의 관련 무기에도 개별 크기를 선택한 뒤 카드 고정을 사용할 수 있게 한다. 계열 제목은 고정 대상으로 사용하지 않는다.

직접 고정은 대상이 같은 스냅샷의 한 정의로 확인된 경우에 실행한다. 정의가 확정돼 있으면 일부 수치가 자료 없음/미지원이어도 해당 상태를 보존해 고정할 수 있다. 중복 후보이면 사용할 정의를 선택하고, 누락·지원 범위 밖이면 상세에서 상태를 알린다. 이름이나 ID 접미사로 크기·상위 단계·해금 관계를 추정하지 않는다. 같은 ID가 기술과 부품 양쪽에 있어도 대상 종류를 구분한다.

고정 여부는 선택한 자료·종류·개별 정의를 기준으로 표시한다. 이미 고정된 대상에는 기존 카드 선택을 제공한다. 연결 목록은 기본 20개/최대 100개와 기존 더 보기를 사용하고, 이동·언어·설정 변경 후 이전 목록의 선택을 새 대상에 적용하지 않는다.

요구 기술 표시는 현재 제국의 연구 보유 상태나 무기 사용 가능 판정이 아니다. 요구 기술이 없거나 목록이 부분적이면 보유 완료·즉시 사용 가능으로 표시하지 않는다.

## 7 중복과 새 카드 배치

신규 고정은 종류 + 스냅샷 + 부품 ID + 개별 정의를 기준으로 동일 카드를 찾는다. 표시 항목이 다르다는 이유로 같은 정의를 중복 추가하지 않는다. 다른 크기·다른 자료·별도 정의는 다른 카드로 유지하며 이름으로 합치지 않는다.

이미 고정된 카드를 다시 누르면 카드 목록에서 선택한다. 편집 상태에서 카드가 보이면 테두리를 짧게 강조할 수 있다. 현재 보기/숨김 상태·게임 초점·공통 숨김 설정은 이 동작으로 바꾸지 않는다. 기존 카드의 표시 항목·순서·위치·크기는 보존한다.

새 카드는 현재 보이는 게임 영역 안에서 기존 카드와 겹치지 않는 위치를 먼저 사용한다. 연결에서 추가했다면 원본 카드 옆의 빈 공간을 우선한다. 충분한 빈 영역이 없으면 제목과 조작부가 화면 안에 남는 계단 배치를 사용한다. 기존 카드를 자동 정렬하거나 움직이지 않는다. 게임 창 정보가 없을 때는 안전한 초기 좌표를 저장하고, 게임을 찾은 뒤 화면 범위로 제한한다.

모든 카드 종류가 기존 전체 24장 한도를 공유한다. 한도에 도달하면 목록을 열어 정리할 수 있게 하고 새 카드의 설정·창은 추가하지 않는다. 버튼을 연속으로 눌러도 같은 정의의 고정 요청을 합치고 실제 추가 직전에 중복과 한도를 다시 확인한다.

고정 해제와 중복 정리는 서로 다른 동작이다. 중복 정리는 기존 저장 설정의 복제 카드를 정리할 때만 사용하며 원래 카드의 사용자 설정이 다른 경우 임의 합치기를 하지 않는다.

## 8 저장과 재시작 호환

새 무기 카드 설정은 kind=weapon, domain=component_template, UID, snapshot_id, game_id, entity_key, 선택 항목과 rect를 저장한다. entity_key가 확정된 개별 정의만 신규 고정한다. 수치·게임 원문·파생 요약은 desktop.json에 저장하지 않고 기존 개인 자료 저장소에서 다시 읽는다.

새 카드에는 무기용 초기 항목을 적용한다. 기존 기술/참조/변경 카드의 생략된 기본 항목·순서·좌표·UID를 무기 기본값으로 채우지 않는다. 신규 무기 카드의 허용 항목/도메인/스냅샷 형식을 구분하고 알 수 없는 종류를 참조나 패치 비교로 해석하지 않는다.

기존 설정 파일 버전의 읽기 호환을 유지하는 추가 변경으로 설계한다. 기존 버전의 실행 파일로 되돌릴 경우 새 카드 종류를 읽지 못할 수 있으므로 최초로 무기 카드 설정을 저장하기 전에 원래 설정 백업을 한 번 남기고 위치를 알려준다. 백업에 실패하면 새 종류를 저장하지 않고 기존 설정을 유지한다. 구형 실행 파일과의 동시 설정 쓰기는 지원 범위에 넣지 않으며 새 설정을 구형 실행 파일에 그대로 넘기는 되돌리기 경로는 제공하지 않는다. 설정 구조를 더 크게 바꿔야 하면 별도 마이그레이션 설계로 분리한다.

고정·해제·순서·항목·갱신은 변경 후보를 검토하고 기존 임시 파일 저장/교체가 성공한 뒤 메모리 목록과 창에 반영한다. 실패하면 원래 파일·카드·순서를 유지한다. 이동·크기는 기존 지연 저장을 사용하고 실패 시 마지막 저장 위치와 화면 상태를 일치시킨다. 같은 설정 경로의 저장은 한 실행 주체로 제한하고, 파일이 외부에서 바뀌었으면 과거 메모리 목록으로 바로 덮어쓰지 않고 다시 읽기를 안내한다. 저장 잠금과 파일 세대 확인은 이 설정 경로에 한정하고 별도 서비스는 추가하지 않는다. 개인 자료는 게임 폴더 밖에 저장한다. 이 구성은 [Python os.replace](https://docs.python.org/3.12/library/os.html#os.replace)의 파일 교체 동작과 기존 저장 코드를 활용한다.

게임과 앱을 다시 켜면 기술·무기 카드의 순서·위치·크기·선택 항목과 기존 공통 투명도를 복원한다. 개별 카드에 새 투명도나 별도 테마 설정은 만들지 않는다.

## 9 새 자료와 갱신 확인

새 색인과 홈의 조회 자료 선택은 기존 고정 카드를 바꾸지 않는다. 과거 카드에서 새 자료로 보기는 상세 조회만 전환한다. 저장된 원본이 없는 과거 카드에는 자료를 읽을 수 없다고 표시하고 삭제·다른 스냅샷의 값 대입은 하지 않는다.

최신 정의 선택·갱신은 같은 부품 ID의 새 자료 후보를 찾는다. 대상 선택 후 이름·크기·기본 여섯 항목·선택 추가 항목·자원·요구 기술·상위 부품의 전후 값을 확인한다. 자료 갱신으로 슬롯 크기가 달라져도 이전 크기로 강제 보정하지 않고 전후 차이를 표시한다.

확인 대상은 출발 카드의 UID/정의/언어/항목/설정 세대와 선택한 새 스냅샷/정의에 고정한다. 확인창을 연 뒤 언어·저장소·카드·대상이 바뀌면 옛 확인 결과를 적용하지 않는다. 적용 직전에 카드 존재·대상 유효성·중복을 다시 확인하고 같은 전후 내용에만 적용한다. 추가 색인으로 활성 자료만 바뀐 경우에도 확인한 대상을 다른 새 자료로 바꾸지 않는다.

적용 시 UID·순서·좌표·크기·항목을 보존한다. 새 대상이 이미 고정돼 있으면 기존 새 카드 선택 또는 취소를 제공한다. 정의 누락·읽기 실패·취소는 기존 카드를 유지한다. 카드 관리의 현재 데이터와 비교는 이 무기 자료 전후 확인으로 연결한다. 기술/이벤트용 비교 요청에 무기 ID를 보내지 않는다.

이 전후 확인은 한 카드의 자료 갱신 기능이다. 서로 다른 두 무기의 비교 화면과 차이 강조는 다음 단계로 둔다.

## 10 응답과 성능과 실패 처리

기존 WeaponService의 수치·자원·상태·관계에서 카드용 표시 데이터를 만든다. 숫자나 조건을 다시 계산하는 카드 전용 파서를 만들지 않는다. 원문 검증·출처 보존·CSV/TXT 정책과 현행 부분 자료 사용 절차를 유지한다.

카드 요청과 응답에는 UID·종류·자료·ID·정의·언어·저장소/게임 경로 설정 세대·요청 번호를 묶는다. 응답 반영 시점에도 현재 카드와 대조한다. 삭제/갱신/설정 변경으로 취소한 요청의 뒤늦은 응답은 버린다. Qt는 연결 해제 후에도 이미 대기 중인 호출이 전달될 수 있음을 명시하므로 요청 취소만으로 응답 유효성을 대신하지 않는다. [QObject 연결 해제](https://doc.qt.io/qt-6/qobject.html#disconnect).

카드 표시용 응답은 기존 상세 응답 한도 64KiB 안에서 개별 정의의 핵심값과 필요한 관계를 투영한다. 많은 자원·관계는 일부 목록과 추가 수를 전달하고 상세의 페이지 요청으로 읽는다. 응답이 길다는 이유로 카드 정체성과 정상 기본 수치를 함께 버리지 않는다.

게임 창 위치 추적은 기존 주기를 사용한다. 정적 무기 조회를 게임 추적 타이머나 매 화면 그리기에서 실행하지 않는다. 최초 고정·재시작·언어/저장소 변경·명시적 카드 갱신·다시 읽기 시에 필요한 자료만 요청한다. 순서·위치·표시 항목만 바뀌면 받아둔 같은 자료를 다시 그린다.

새 고정/해제/갱신은 해당 UID의 창과 요청만 변경한다. 다른 카드 창을 전부 닫아 다시 만들거나 전체 카드의 CSV를 재조회하지 않는다. 기존 기술/참조/변경 카드도 같은 관리 경로에서 보존하되 무관한 구조 교체는 하지 않는다. DB 연결은 기존 작업 스레드가 소유한다.

읽기 실패는 카드별로 처리한다. 그 카드의 정상 수치 자리를 비우고 자료 읽기 실패와 편집 상태의 다시 읽기/관리 경로를 제공한다. UID와 배치는 유지하며 다른 카드 표시는 계속한다. 오류가 난 현재 요청에 과거 정상값을 남겨 현재값처럼 표시하지 않는다. 자료 없음·출처 손상·원문 정책 밖 상태는 각각 구별하며 반복 진단을 게임 위에 나열하지 않는다.

## 11 배율과 창 복원

위치·크기는 기존 게임 클라이언트 기준 96 DPI 저장 좌표를 사용한다. Qt 위젯의 논리 좌표와 Windows 네이티브 좌표를 혼용하지 않고 네이티브 배치/좌표 수집 경계에서만 변환한다. 창 크기나 글꼴에 배율을 두 번 곱하지 않는다.

모니터·창 크기·배율이 바뀌면 현재 게임 영역과 해당 창의 배율로 배치한다. 자동 숨김이나 게임 최소화 중 관측한 빈 영역으로 저장 위치를 덮어쓰지 않는다. 재배치가 필요한 카드만 현재 화면 안으로 복구한다. 다른 모니터의 좌표가 연결돼 있다고 가정하지 않는다. Qt의 [High DPI 좌표 모델](https://doc.qt.io/qt-6/highdpi.html)을 적용하는 경계다.

게임 상실·최소화·창 전환 시 숨김과 복귀, 앱 종료 시 창 정리, 단축키 충돌 처리와 게임 식별은 기존 공통 흐름을 유지한다. 이 단계에서 새로운 게임 화면 인식·메모리 접근·그래픽 주입은 추가하지 않는다.

## 12 개발 범위와 필수 완료 확인

이번 범위는 무기 카드 요약과 항목 설정, 개별 고정/중복 방지/고정 해제, 기존 기술과 혼합 저장·복원, 같은 자료의 연결 선택과 추가 고정, 전후 확인을 통한 개별 갱신이다. 현재 Qt/서비스/저장 방식 안에서 구현한다.

별도 두 무기 비교 화면·승자/추천·DPS·변이/모드 적용 결과·세이브 보유 판정·함선 자동 변경·게임 위 무기 검색창·카드 묶음/자동 정렬/개별 테마는 후속이다. 카드 두 장을 수동으로 고정하는 것은 이번 범위에 포함한다.

개발 순서는 설정/종류별 표시 응답 → 무기 요약과 항목 선택 → 고정/해제/부분 창 갱신/저장 → 기술·상위 부품 선택/추가 고정 → 과거 자료 갱신/응답 일관성/배치 복원이다. 기능 작성 진행률 100% 이후 아래 필수 항목만 검사한다.

- 실제 개별 크기 무기 카드의 기본 여섯 항목과 자원, 부분/동적 값의 구분, 관리창과 동일 수치.
- 작은 카드·긴 이름/숫자·여러 자원과 조건·생략 항목 복원, 배율 변경 시 글자/좌표 중복 확대 방지.
- 요구 기술/명시 상위 부품의 같은 자료 이동·직접 추가 고정·중복 후보 선택과 24장 한도/연속 클릭.
- 보기 입력 통과·편집 동작·전체 숨김/한 장 고정 해제, 기존 카드가 깜박이거나 이동하지 않는 추가/제거.
- 기존 카드 설정 호환/백업·저장 실패/외부 설정 변경 보존·재시작, 과거 카드/갱신 전후/확인 중 변경/늦은 응답과 카드별 실패.
- 최종 실행 파일에서 위 흐름이 연결되는 최소 확인과 변경 부분의 회귀.

완료 기준은 청색 레이저 기술에서 소형 무기를 고정하고 연결 목록에서 필요한 기술과 상위 무기를 추가한 뒤, 게임으로 돌아가 입력을 방해하지 않고 카드를 읽고 편집·고정 해제·재실행 복원하는 흐름이다. 커밋·푸시·PR·병합·배포는 별도 실행 범위로 둔다.
