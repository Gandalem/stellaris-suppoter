# refs 개발 초안 — 2안

## 목표

기술의 선행 관계와 이벤트의 정적 참조를 조회한다. 각 관계에는 원본 파일과 행을 연결하고, 같은 기능을 CLI·관리창·게임 오버레이에서 함께 사용한다.

## 사용자 흐름

1. 검색한 기술이나 이벤트의 상세 화면에서 참조 관계를 연다.
2. 직접 연결된 대상을 목록으로 확인한다.
3. 대상을 선택하면 상세 정보와 다음 참조로 이동한다.
4. 필요한 깊이까지 관계를 펼치고 원본 위치를 확인한다.
5. 오버레이에서는 보고 싶은 항목을 카드로 고정한다.

## 기능 구성

| 기능 | 동작 |
|---|---|
| 기술 선행 관계 | 선택한 기술의 선행 기술을 직접·다단계로 조회 |
| 이벤트 참조 | 지원 구문에 명시된 이벤트 ID를 연결 |
| 정의 선택 | 같은 ID의 정의가 여러 개면 후보 목록에서 선택 |
| 관계 상태 | 연결됨·미해결·모호함을 구분 |
| 순환 표시 | 반복되는 연결을 표시하고 같은 경로의 확장을 중단 |
| 원본 보기 | 관계가 기록된 파일·행·원문 위치 표시 |
| 조회 범위 | 깊이와 결과 수를 조절하고 선택한 스냅샷 유지 |

## 명령 구성

- refs 기술ID: 직접 선행 관계 조회
- refs 기술ID --depth 3: 3단계까지 조회
- refs 기술ID --snapshot 스냅샷ID: 지정한 데이터에서 조회
- refs 기술ID --entity-key 정의ID: 동명 정의 중 하나를 선택
- refs 이벤트ID --kind event: 이벤트 참조 조회

기술과 이벤트는 정확한 ID로 선택한다. 이름 검색은 기존 검색 화면에서 처리하고, 선택한 정의를 refs에 전달한다.

## 화면 연결

관리창에는 검색 결과·상세 정보·참조 목록·원본 보기를 배치한다. 오버레이에는 검색창·간단한 상세 카드·참조 목록을 배치하고 카드 고정을 지원한다. 두 화면은 같은 참조 서비스를 호출한다.

## 내부 구조

기존 파서와 SQLite를 활용하고 참조 조회 서비스를 추가한다. 서비스는 선택한 스냅샷의 엔티티와 관계를 읽고, 관계 해석·탐색·출처 연결·결과 구성을 담당한다. CLI와 화면은 서비스 결과를 표시한다.

게임 원본은 읽기 전용으로 사용한다. 관계의 방향·중복 정의·원문 순서를 보존하며, 다른 스냅샷의 데이터를 섞지 않는다. 연구 가능 여부·이벤트 실행·발생 확률 계산은 별도 기능으로 둔다.

## 개발 순서

1. 조회 인자와 공통 응답 구조 작성
2. 기술 선행 관계 조회와 원본 연결 구현
3. 다단계 탐색·누락·동명·순환·조회 한도 처리
4. CLI 연결
5. 이벤트 참조 추출·저장·조회 연결
6. 관리창과 오버레이에서 사용할 호출 인터페이스 정리
7. 기능 구현 진행률 100% 도달 후 검증·검수 진행
8. 검수에서 발견한 사항 수정 및 최종 정리

## 작업 방식

개발 중에는 구현 내용과 진행률만 기록한다. 설명 문서와 진행 보고에 미구현 안내나 검증 예정 문구를 항목마다 반복하지 않는다. 테스트 실행·검증·검수는 기능 구현 진행률 100% 이후에 진행한다.
