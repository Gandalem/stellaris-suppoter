# 작업 명세 템플릿

이 파일을 새 작업 기록으로 복사해 채웁니다. placeholder를 실제 실행 결과로 오해하지 않습니다. 원장의 상태는 [tasks.json](../tasks.json)에서 관리합니다.

## 식별·범위

작업 ID: TASK-___
제목:
관련 기능 / 평가 ID:
기준 브랜치와 commit:
선행 작업 및 완료 근거:
사용자 요청과 이 작업의 연결:

이번에 구현할 것:
이번에 구현하지 않을 것:
수정·추가할 파일:
참조할 요구사항·데이터 계약:
미확인 가정과 확인 방법:

## 수용 조건

입력 → 기대 출력:
실패·unknown·partial 동작:
필수 합성 fixture와 provenance:
인용·snapshot·읽기 전용·네트워크 경계:
호환성·성능에 관해 실제 측정할 것:

## 검증 계획과 결과

| 명령/평가 | 환경 | 실행 여부·exit code | 결과 | evidence |
|---|---|---|---|---|
| 작성 전 | 미정 | not_run | 미확인 | 없음 |

계획한 명령과 실제 실행한 명령을 구별합니다. 외부 접근이나 실제 게임 데이터가 필요한 검사는 별도로 적습니다. 실패한 검사를 삭제해서 완료 기준을 바꾸지 않습니다.

## 종료

구현 산출물:
미완료/제약:
검토자 또는 self_review:
복구·rollback:
원장에 적용할 상태 변경과 근거:
다음 작업:

수용 조건·의존 작업·관련 평가·실행 evidence가 모두 충족되어야 done입니다. 막힌 경우 blocker와 해제 조건을 적고 다른 독립 작업의 진행 가능 여부를 확인합니다.
