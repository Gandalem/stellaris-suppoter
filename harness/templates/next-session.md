# 다음 세션 시작 프롬프트

아래 본문을 구현 에이전트에게 전달합니다. 사용자 지시·권한·안전 규칙이 우선이며 이 문서는 추가 권한을 부여하지 않습니다.

---

저장소 Gandalem/stellaris-suppoter에서 작업한다. 먼저 현재 브랜치·HEAD와 기존 변경을 확인하고 AGENTS.md, harness/state.json, 마지막 세션 기록, harness/tasks.json을 읽는다. 연결된 실제 파일을 조회하지 않고 과거 채팅만으로 상태를 가정하지 않는다.

state.next_task의 선행 작업과 연결된 요구사항·설계·평가를 확인한다. 처음 상태의 다음 작업은 TASK-001: Python 패키지와 개발 환경이다. 제품 코드가 이미 생겼는지 확인하고 중복 생성하지 않는다.

harness/templates/task.md 형식으로 범위·수정 파일·수용 조건·검증 계획을 기록한다. 실행 가능한 작업 하나만 doing으로 전환한다. 합성 실패 재현을 먼저 만들고 최소 구현 후 관련 테스트를 실행한다. 현재 가능한 문서 검사 명령은 다음과 같다.

```sh
python scripts/check_harness.py
python -m unittest discover -s tests_harness -v
```

제품 테스트·CLI가 아직 없으면 실행했다고 보고하지 않는다. TASK-001 이후 만들어진 실제 명령은 문서와 함께 갱신한다. 제품의 설치·API·모델·실제 게임 검증은 문서 검사와 다르다.

게임 폴더는 읽기 전용이다. 실제 게임/DLC/모드/번역/세이브/DB/키/개인 경로를 공개 저장소에 넣지 않는다. 외부 전송·유료 API·모델 다운로드·게임 자동 조작을 임의 실행하지 않는다. 버전·DLC·모드 로드 규칙·게임 엔진 의미가 불명확하면 unknown 또는 unsupported로 유지한다.

종료 시 실제 실행 명령·결과·환경·evidence를 기록하고 tasks/features/evals/state와 세션 기록을 갱신한다. 모든 수용 조건과 관련 평가가 확인되기 전 done/verified/pass를 부여하지 않는다. 변경은 작업 브랜치와 PR로 전달하고 자동 병합·릴리스는 별도 승인 없이 하지 않는다.

최종 보고는 완료한 변경, 실제 검증, 미완료·제약, 다음 단일 작업을 구별한다. 백그라운드로 계속 작업한다고 약속하지 않는다.
